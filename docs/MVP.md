# v0.1 범위 (MVP)

> 기준일 2026-10-09, 작성 차수 S01. 근거: [BUSINESS_CONTEXT 11절 로드맵](BUSINESS_CONTEXT.md) · 설계: [ARCHITECTURE](ARCHITECTURE.md) · 위협: [THREAT_MODEL](THREAT_MODEL.md)
> S32가 이 문서의 [6절 'v0.1 완료'의 정의](#6-v01-완료의-정의)를 항목별로 채점한다(충족 / 실기 확인 대기 / 미충족 + 사유). 범위를 바꾸려면 이 문서와 ADR을 같은 커밋에서 고친다.
> SLO의 숫자는 모두 **목표**다. 측정값이 아니다. 측정한 차수가 결과를 REPORT와 E2E 보고서(S27, `docs/E2E_REPORT.md`)에 적는다.

## 1. 한 문장
v0.1은 **"동네 PC방 1~3곳에서 파일럿을 시작할 수 있는 상태"**다. 0단계(친구 PC 장난감)를 완성하고, 1단계(PC방 파일럿, 현금 정산은 사람이 시스템 밖에서)를 운영할 수 있는 코드·문서·도구를 갖추고, 2단계(선불 크레딧 판매, 외부 모델 환전)는 **켜기만 하면 되도록 만들되 스위치로 잠가 둔다**.

로드맵의 '다음 단계로 넘어가는 조건'(1단계: 월 수익·전기요금 실측, 2단계: 첫 유료 고객 + 법률 검토)은 사람이 파일럿에서 달성하는 것이다. v0.1 완료 조건이 아니다.

|---|---|---|---|

## 3. 스위치로 잠그는 것 (기본값은 모두 '꺼짐')
상세 표는 [ARCHITECTURE 10절](ARCHITECTURE.md#10-안전-스위치와-기능-플래그). v0.1에서 바뀌면 안 되는 기본값만 다시 적는다.

| 기능 | v0.1 상태 | 잠금 방식 | 풀려면 |
|---|---|---|---|
| 실결제 | 없음 | `PAYMENTS_MODE=live`면 서버 시작 거부 | 법률 검토 + 결제 대행 계약 + 새 차수(사람 결정) |
| 현금 출금(cash-out) | **코드가 없다** | `CASHOUT_ENABLED=true`면 시작 거부. 정산은 운영자의 '기록'(`MANUAL_PAYOUT_RECORD`)뿐, 실제 송금은 시스템 밖 | 법률 검토 뒤 새 ADR |
| 외부 모델 실제 호출 | Mock | 세 겹 스위치(`EXTERNAL_PROVIDERS`, API 키, `EXTERNAL_LIVE_CONFIRM=yes`) + CR 지갑 + 일일 달러 상한 | 사람이 키를 넣고 세 개를 모두 켠다(HUMAN_TODO, S16) |
| 바스켓 페그 | 꺼짐 | `peg_basket` DB 플래그, 기본 달러 고정(ADR 0014) | 실험 목적, 운영자 |
| 발행형(난이도 조절) | 시뮬레이터 전용 | `issuanceMode`가 `marketplace`가 아니면 시작 거부(ADR 0013) | 토큰 발행 합법화 + 새 ADR |
| 다중 서버 인스턴스 | 꺼짐(단일) | 배포 설정 | 노드 1,000대 근처(ARCHITECTURE 8절 단계 B) |
| 개발 편의(`DEV_AGENT_SECRET`, `DEV_DASHBOARD`, `--always-available`) | 개발 전용 | 운영에서 설정돼 있으면 시작 거부, 서비스 모드에서 거부 | 풀지 않는다 |

## 4. 명시적 비목표 (v0.1에서 하지 않는다)
| 비목표 | 이유 |
|---|---|
| 실제 돈 결제·출금·자동 송금 | 절대 규칙 2. 법률 검토 전 |
| 거래 가능한 토큰, 토큰 발행·판매 | 한국 ICO 금지(BUSINESS_CONTEXT 10절), ADR 0006 |
| 큰 모델을 여러 PC에 쪼개 실행 | 인터넷이 병목(BUSINESS_CONTEXT 4절 3번). 한 PC에 들어가는 중소형 모델만 |
| 텍스트 생성 외 작업(이미지 생성, 음성, 임베딩, 미세조정·학습) | 런타임·검증·과금이 텍스트 LLM 기준. 이미지 생성은 사업 문서의 후보지만 v0.1 밖(ARCHITECTURE 12절 관찰) |
| 민감 데이터 처리(신뢰 실행 환경, 기밀 컴퓨팅) | 남의 PC에서 평문 처리는 막을 수 없다(THREAT_MODEL AGT-12). 구매자에게 '민감 데이터 금지'로 안내 |
| NVIDIA 외 GPU(AMD, Intel), 리눅스·macOS 에이전트 | PC방 GPU는 대부분 NVIDIA라는 가정. 다른 OS는 개발용 노드 시뮬레이터만 |
| PC방 관리 프로그램(요금·좌석 관리) 연동 | 꽂을 자리만 남긴다. 제휴 시 연결(ARCHITECTURE 11절 2번) |
| 구매자 대상 가용성 보장(SLA), 다중 리전, 무중단 배포 | 1인·저비용 운영. 단일 인스턴스 장애는 수용(THREAT_MODEL DATA-07) |
| 사장님 앱(모바일 네이티브), 알림톡·문자 | 휴대폰 브라우저 대시보드로 충분. 알림은 대시보드 배지·이메일 수준 |
| 세금 계산서·회계 연동, 원화 자동 환산 지급 | 정산은 사람이 기록. 환산 시점·세금은 미정(ARCHITECTURE 12절 관찰) |
| 다국어 완성 | 한국어 기본. 영어 키는 구조만(S23) |
| 구매자 콘텐츠를 사람이 열람하는 기능 | ADR 0010. 검토 화면은 해시·점수·길이만 |

## 5. SLO (목표)
측정 위치: '시뮬레이션'은 노드 시뮬레이터(S17)와 시스템 E2E(S27)의 가짜 런타임, '실기'는 Windows + NVIDIA GPU 실제 PC(`docs/manual-tests/`). 시뮬레이션으로 잴 수 없는 것은 실기 확인 전까지 '실기 확인 대기'로 남는다.

| ID | 지표 | 목표 | 정의 | 측정 | 근거 |
|---|---|---|---|---|---|
| SLO-1 | 선점: 손님 입력 → 런타임 프로세스 종료 | p95 ≤ 0.5초 | 헬퍼가 본 입력 시각 t0 → Job Object 종료 확인. 에이전트가 3구간(감지·전달·종료)으로 기록 | 실기 S18(시뮬레이션은 경로 검증만) | 손님이 앉아 첫 화면을 보기 전에 멈춘다(T5) |
| SLO-2 | 선점: 손님 입력 → VRAM 해제 | p95 ≤ 2초 | t0 → nvidia-smi에서 우리 프로세스 VRAM 0 | 실기 S18·S19 | 게임 로딩보다 짧게(T6) |
| SLO-3 | 작업 성공률 | ≥ 99% | 완료 / (전체 − 구매자 원인 종료). 구매자 원인 = 잘못된 입력, 구매자 취소·연결 끊김, 잔액 부족. 마감 초과·재시도 소진·잃어버린 작업은 실패로 센다 | 시뮬레이션 S27 시나리오 1(평상시) 3회. 다른 시나리오는 기록만 | 선점·재배정이 구매자에게 보이지 않아야 한다 |
| SLO-4 | 원장 대사 차이 | 항상 0 | 대사(통화별 합 0, 잔액 = 기입 합, 홀드·미성숙 = 개별 합)의 차이 행 수와 금액 | 모든 시나리오 끝과 매 대사 주기(T29) | 돈은 정수·원장으로만(절대 규칙 3). 차이 ≠ 0이면 자동 `ledger_frozen` |
| SLO-5 | API 오버헤드 | p95 ≤ 300ms | 서버 안에서 쓴 시간 = (요청 수신 → 오퍼 전송) + (노드 청크 수신 → 구매자에게 쓰기, 청크마다 최대값) + (완료 수신 → 응답 종료). 용량 대기 시간과 추론 시간은 제외하고 따로 보고 | 시뮬레이션 S27(가짜 노드, 지연 0) | 대화형 체감에서 우리가 더하는 몫을 작게 |
| SLO-6 | 킬스위치 전파 | 최대 ≤ 1초 | 킬스위치 저장 커밋 → 범위 안 연결된 모든 노드의 ack. 연결 안 된 노드는 T13(10초 자가 정지)로 따로 보장 | 시뮬레이션 S11(p95), S27 시나리오 9(최대) | 사장님·운영자의 '멈춤' 기대(T16) |
| SLO-7 | 선점 → 재배정 서버 처리 | p95 ≤ 1초 | `job.preempted` 수신 → 다음 노드에 오퍼 전송(가용 노드가 있을 때) | 시뮬레이션 S12, S27 시나리오 2 | 구매자 스트림 공백 최소화(T18) |
| SLO-8 | 돈·작업 불변식 | 위반 0 | 미해결 홀드 0, 이중 캡처 0, 잃어버린 작업 0(모든 작업이 완료·실패·취소·만료 중 하나), 킬스위치 이후 작업 시작 0 | 시뮬레이션 S27 모든 시나리오 × 3회 | ARCHITECTURE 9.5 M1~M9 |
| SLO-9 | 콘텐츠 유출 | 0회 | 로그·지표·에러·감사·노드 디스크에서 표식 문자열 발견 수 | 자동 테스트 S05·S14·S17·S22, 감사 S28 | 절대 규칙 4 |

- SLO-1·2가 실기에서 미달이면 파일럿을 시작하지 않는다(손님 경험 최우선). 다른 SLO 미달은 원인·대응을 기록하고 사람이 판단한다.
- 서버 가용성은 v0.1에서 목표를 두지 않고 측정만 한다(단일 인스턴스, 4절).
