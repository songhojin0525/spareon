# 용어집 (GLOSSARY)

> 기준일 2026-10-09, 작성 차수 S01. 코드·문서·UI가 같은 말을 같은 뜻으로 쓰게 한다. 상태 이름·시간 값의 정의는 [ARCHITECTURE](ARCHITECTURE.md)가 원본이고, 여기는 뜻만 짧게 적는다.
> 규칙: 사업 문서의 '토큰'(화폐)은 코드·UI에서 항상 **크레딧**이다. '토큰'은 LLM 입력·출력 단위(모델 토큰)만 뜻한다. 코드 이름은 영어, UI 문구는 한국어(i18n 키).

## 1. 사람과 장소

| 용어 | 코드 이름 | 뜻 |
|---|---|---|
| 사장님 | `owner` | PC방 운영자. 매장·PC를 등록하고 수익을 받는다. 역할 이름 |
| 구매자 | `buyer` | 크레딧으로 모델을 쓰는 사람·회사. API 키·포털을 쓴다 |
| 운영자 | `operator` | 우리(창업자 1인). 가격·검증·정산 기록·킬스위치를 다룬다. CLI로만 만든다 |
| 손님 | — | PC방에서 PC를 쓰는 사람. 시스템의 사용자가 아니다. 손님의 입력 '시각'만 본다 |
| 매장 | `store` | PC방 1곳. 정책·등록 코드·수익 계정의 단위 |
| 노드 | `node` | 에이전트가 설치된 PC 1대 |
| 신뢰 노드 | `trusted node` | 운영자가 지정한 노드(예: 운영자 PC). 카나리아 정답 생성, 3자 판정, TCR 작업에 쓴다 |
| 차수 | `SNN` | 이 저장소의 작업 단위(S00~S32). `prompts/STAGES.md` |

## 2. 돈

| 용어 | 코드 이름 | 뜻 |
|---|---|---|
| 크레딧 | `CR` | 선불 연산 크레딧(ADR 0006). 화폐가 아니고 출금할 수 없다. 1 CR = 1,000,000 µCR |
| 마이크로크레딧 | `µCR`, 코드 `ucr` | 크레딧의 최소 단위. bigint 정수로만 다룬다(ADR 0005) |
| 샌드박스 크레딧 | `TCR` | 구매자 셀프 테스트 충전으로 생기는 별도 통화. 정산·실제 외부 호출·준비금으로 갈 수 없다(ARCHITECTURE 12절 D2) |
| µUSD, 원 | `uusd`, `krw` | 달러 최소 단위(1달러 = 1,000,000 µUSD), 원화(정수 원) |
| 원장 | `ledger` | 모든 잔액 변화를 기록하는 이중기입 장부. 잔액을 바꾸는 유일한 모듈 |
| 이중기입 | double entry | 거래마다 통화별 기입 합이 0. 돈은 계정 사이를 옮겨 갈 뿐 생기거나 사라지지 않는다(예외는 정해진 출처 계정) |
| 거래 / 기입 | `ledger_tx` / `ledger_postings` | 원장 거래 1건과 그 안의 계정별 증감 |
| 멱등 키 | `idempotencyKey` | 같은 거래를 두 번 실행해도 한 번만 반영되게 하는 키(예: `job:<id>:capture`) |
| 홀드 | `hold` | 작업 시작 전 구매자 지갑에서 최대 비용을 묶어 두는 것 |
| 캡처 | `capture` | 홀드에서 실제 비용을 가져가는 것. 작업당 최대 1번, 홀드를 넘지 않는다 |
| 해제 | `release` | 홀드의 남은 금액을 지갑으로 돌려주는 것 |
| 노드 몫 / 플랫폼 몫 | `payoutBps` | 비용 중 매장에 가는 비율(만분율, 내림)과 나머지 |
| 미성숙 수익 | `earning.pending` | 캡처 뒤 성숙 기간(기본 72시간) 동안 보류된 매장 수익 |
| 확정 수익 | `earning.matured` | 성숙 기간이 지나 정산 기록이 가능한 수익 |
| 보류 | `earning.held` | 노드 격리·조사 중이라 성숙이 멈춘 수익 |
| 회수 | `EARNING_CLAWBACK` | 확정된 부정에 연결된 미성숙·보류 수익을 되돌리는 것. 성숙한 수익은 운영자 검토로만 |
| suspense | `suspense` | 회수한 돈이 환불·조정 전 머무는 계정(보류·조사 계정) |
| 정산 기록 | `MANUAL_PAYOUT_RECORD` | 운영자가 사장님께 지급할 확정 수익 건을 묶어 기록하는 것(정산 처리 중). 실제 송금 기능은 없다 |
| 송금 확인 | `PAYOUT_SETTLED` | 시스템 밖 송금을 확인한 기록. 정산 처리 중(CR)을 없애고 준비금(KRW) → 정산 지급(KRW) |
| 테스트 충전 | `TEST_TOPUP` | 운영자가 창업자 자금 입금을 기록해 CR과 준비금을 만드는 것(파일럿용). 실결제 아님 |
| 샌드박스 충전 | (거래 종류 이름은 S06이 정한다) | 구매자 셀프 충전. TCR만 만든다 |
| 준비금 | `reserve` | 크레딧 판매 대금(원화). 외부 모델 환전의 재원 |
| 부채 | `liabilities` | 준비금으로 갚아야 할 것 = 구매자 CR + 매장 CR 수익(ARCHITECTURE 9.4) |
| 준비금 비율 / 가드 | `reserveMinRatio` | (준비금 − 미정산 예약 합 − 이번 예약) / 부채. 기준 미만이면 외부 환전 거부(ARCHITECTURE 9.4) |
| 일일 한도 | `dailyCap` | 사용자별·전체 외부 환전 하루 상한 |
| 페그 | `peg` | 1 CR의 가치 기준. 기본 달러 고정(`UsdFixed`), 바스켓(`Basket`)은 실험 플래그(ADR 0014) |
| 환율 스냅숏 | `fx_rates` | 원화·달러 환율 기록. 7일 넘으면 노후로 보고 외부 환전·테스트 충전을 막는다 |
| 가격 버전 | `price_versions` | 모델별 단가표의 한 버전. 작업 생성 시 고정된다 |
| 대사 | `reconciliation` | 잔액·기입·홀드·미성숙 합이 맞는지 주기적으로 확인하는 것 |
| 원장 동결 | `ledger_frozen` | 대사 차이 발견 시 자동으로 켜지는 플래그. 외부 환전·성숙·정산 기록이 멈춘다 |
| 마켓플레이스 방식 | `issuanceMode=marketplace` | 노드 보상이 구매자 지불에서만 나온다. 기본이자 유일한 운영 모드(ADR 0013) |
| 발행형 | `issuanceMode` ≠ `marketplace` | 새 크레딧을 찍어 보상하고 난이도를 조절하는 방식. 시뮬레이터 전용 |
| 외부 모델 환전 | `EXTERNAL_EXCHANGE` | 크레딧으로 Claude 같은 외부 모델을 쓰는 것. 준비금으로 원가를 낸다 |
| 세 겹 스위치 | — | 외부 실제 호출에 필요한 환경변수 세 개(`EXTERNAL_PROVIDERS`, API 키, `EXTERNAL_LIVE_CONFIRM=yes`) |

## 3. 작업과 실행

| 용어 | 코드 이름 | 뜻 |
|---|---|---|
| 작업 | `job` | 구매자 요청 하나(대화형 1건 또는 배치 1줄). 상태는 ARCHITECTURE 5.2 |
| 시도 | `attempt` | 작업 하나를 노드 하나가 실행한 1회. 선점·실패로 여러 번 생긴다. 상태는 ARCHITECTURE 5.3 |
| 모델 토큰 | `tokensIn` / `tokensOut` | LLM 입력·출력 단위. 과금용 수는 서버가 센다(ADR 0009) |
| 대화형 / 배치 | `interactive` / `batch` | 바로 응답하는 요청(스트리밍 가능) / JSONL 파일로 올리는 대량 작업(마감 24시간) |
| 오퍼 | `job.offer` | 서버가 노드에 작업을 제안하는 메시지. 2초 안에 수락해야 한다 |
| 리스 | `lease` | 실행 중 시도의 소유권. 마지막 갱신 + 15초에 만료 |
| 하트비트 | `heartbeat` | 에이전트가 5초마다 보내는 생존 신호 |
| 재개 창 | `resume window` | 연결이 끊긴 세션을 이어 붙일 수 있는 시간. 마지막 수신 + 10초 |
| 진행 없음 제한 | `progress timeout` | 수락 뒤 첫 청크 60초, 청크 사이 30초(목표). 넘으면 시도 실패(T35) |
| 마감 | `deadline` | 작업이 끝나야 하는 시각. 대화형 10분, 배치 24시간 |
| 선점 | `preempt` | 손님·킬스위치·온도 등으로 실행 중 시도를 즉시 멈추는 것 |
| 재배정 | `reassign` | 선점·실패된 작업을 다른 노드에 다시 주는 것 |
| 이어쓰기 | `continuation` | 재배정 시 이미 구매자에게 전달된 출력을 접두사로 주고 이어서 생성하는 것 |
| 전달된 토큰 | `deliveredTokens` | 서버가 실제로 구매자에게 쓴 출력 토큰 수. 부분 과금과 이어쓰기 분배의 근거 |
| `inputRef` | `inputRef` | 큰 입력(256 KiB 초과)을 메시지 대신 단기 서명 토큰으로 내려받게 하는 참조 |
| DRR 공정성 | deficit round robin | 대형 배치가 다른 구매자의 요청을 막지 않게 하는 큐 순서 규칙 |
| 안정성 예측 | stability score | 노드가 앞으로 얼마나 오래 빌지에 대한 점수. 오래 빌 노드에 긴 작업을 준다 |
| 늦은 완료 | `superseded` | `lost`·`canceled` 뒤에 도착한 완료. 결과를 버리고 보상하지 않는다 |

## 4. 노드와 에이전트

| 용어 | 코드 이름 | 뜻 |
|---|---|---|

| 헬퍼 | `binjari-helper` | 사용자 세션에서 입력 시각·전체 화면 등을 보고 이름 있는 파이프로 서비스에 알리는 프로그램(ADR 0011) |
| 업데이터 | `binjari-updater` | 버전 폴더 교체와 자동 롤백을 하는 별도 실행 파일 |
| 노드 시뮬레이터 | `nodesim` | 가짜 노드 여러 대를 띄우는 개발·시험 도구 |
| 런타임 | `runtime` | 모델을 실제로 돌리는 프로세스. 운영은 llama.cpp `llama-server`, 개발은 Ollama, 시험은 fake |
| Job Object | — | Windows에서 프로세스 묶음을 한 번에 죽이는 커널 객체. 선점과 고아 런타임 방지에 쓴다 |
| 적격 | `eligible` | 노드가 지금 작업을 받을 수 있음. '모든 조건이 확실히 참'일 때만(ADR 0016) |
| `minIdleMinutes` | `minIdleMinutes` | 손님 입력이 없어야 하는 최소 시간(기본 10분). 선점 뒤 처음부터 다시 센다 |
| 적격 임대 / 데드맨 스위치 | eligibility lease / deadman | 적격 판정 루프가 250ms마다 갱신하는 임대. 1초 넘게 갱신이 없으면 감시 경로가 런타임을 죽인다 |
| 자가 정지 | self-stop | 서버와 10초 넘게 연락이 끊기면 에이전트가 스스로 작업을 멈추는 것 |
| 킬스위치 | `kill_switches` | 노드·매장·전체 범위로 작업을 즉시 멈추고 오퍼를 막는 스위치. 지속 저장 |
| 일시정지 | `paused` | 사장님·운영자가 멈춘 노드 상태 |
| 격리 | `quarantined` | 부정·복제 의심으로 오퍼를 끊은 노드 상태. 운영자가 해제한다 |
| 영구 제외 | `excluded` | 운영자가 부정으로 영구히 뺀 노드 상태. 운영자만 해제한다. 사장님이 끈 `disabled`와 다르다 |
| 고장 | `Faulted` | 에이전트 로컬 상태. 런타임 종료·VRAM 해제를 확인하지 못해 작업 불가로 보고한 상태 |
| 승인 대기 | `pending` | 이미지 코드로 새로 생겨 사장님 승인을 기다리는 노드 상태 |
| 운영자 확인 | `verifiedAt` | 운영자가 실제 매장임을 확인한 시각. 확인 전 매장은 CR 작업을 받지 않는다(D13) |
| 손님 존재 구간 | `presence_intervals` | 노드별 손님 있음/없음 구간(시각만). 안정성 예측과 분쟁 확인용 |

## 5. 신원·배포·PC방 환경

| 용어 | 코드 이름 | 뜻 |
|---|---|---|
| 등록 코드 | `enroll_codes` | 노드 등록에 쓰는 8자 코드. `single`(PC 1대, 24시간) / `image`(매장 단위, 여러 번) |
| 재부착 | re-attach | 같은 매장·같은 하드웨어 지문의 PC가 새 키로 등록할 때 기존 노드에 다시 묶는 것 |
| 복제 | clone | 같은 신원(키)을 가진 PC가 여러 대 생긴 것. 마스터 이미지 사고가 주 원인 |
| 하드웨어 지문 | `fpStore`, `fpGlobal` | GPU UUID 등 원본의 HMAC. 매장 솔트(재부착용)와 전역 솔트(매장 간 중복 탐지용) 두 개(ADR 0008) |
| 영구 폴더 | `PERSIST_DIR` | 복원 솔루션이 되돌리지 않는 드라이브의 폴더. 신원·캐시를 둔다 |
| 복원 솔루션 | — | 재부팅 때 디스크를 되돌리는 PC방 프로그램 |
| 이미지 모드 | `IMAGE_MODE=1` | 마스터 이미지에 설치할 때 키를 만들지 않고 코드만 두는 설치 방식 |
| LAN 캐시 노드 | `CACHE_MODE=server` | 매장 안에서 모델·업데이트 파일을 나눠 주는 지정 PC |
| 아티팩트 | artifact | 서명된 배포 파일(모델, 런타임, 에이전트) |
| 매니페스트 | manifest | 아티팩트의 버전·파일·SHA-256 목록. ed25519로 서명한다 |
| 릴리스 | `agent_releases` | 에이전트 배포 단위. 상태는 ARCHITECTURE 5.6 |
| 단계적 배포 | rollout | 1% → 10% → 50% → 100%처럼 대상을 늘려 가는 배포 |
| 롤백 | rollback | 이전 버전으로 되돌리기. 에이전트 쪽 자동 롤백과 서명된 롤백 매니페스트가 있다 |

## 6. 검증

| 용어 | 코드 이름 | 뜻 |
|---|---|---|
| 카나리아 | canary | 정답을 미리 아는 작업. 일반 작업과 구별되지 않게 섞는다 |
| 중복 실행 | duplicate run | 같은 입력·파라미터·시드를 다른 매장·다른 사장님의 노드에서 한 번 더 돌려 비교하는 것 |
| 모델 지문 | model fingerprint | 모델마다 출력이 확실히 갈리는 짧은 프롬프트. 모델 바꿔치기를 잡는다 |
| 서버 시드 | seed | 서버가 모든 작업에 붙이는 난수 시드. 중복 실행 비교를 가능하게 한다 |
| 판정 | `verdict` | `pass` / `fail` / `inconclusive`. 확정된 판정만 평판에 반영한다 |
| 평판 | reputation | 노드별 베타 분포 사후 평균(시간 감쇠). 낮으면 더 자주 검증하고 오퍼가 줄어든다 |
| 검토 대기열 | `review_queue` | 운영자가 회수·격리를 확정하는 목록. 콘텐츠 없이 해시·점수만 |

## 7. 문서와 작업 방식
