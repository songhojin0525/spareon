# 0008. 기기 신원은 ed25519 키 + 챌린지 응답, 하드웨어 지문은 HMAC 두 개, 이미지 코드로 재부착하고 복제는 양쪽에서 잡는다

- 상태: 채택
- 날짜: 2026-10-08
- 차수: S01

## 맥락
- PC방 PC는 하나의 마스터 이미지를 복제해 깔고, 재부팅하면 C 드라이브가 원래대로 돌아가는 복원 솔루션을 쓰는 경우가 많다(S20). 그래서:
  - 이미지에 신원이 들어가 있으면 모든 PC가 같은 신원을 갖는다(복제).
  - 영구 저장 위치가 없으면 재부팅마다 신원이 사라져 새 노드가 생긴다.
- 노드 신원은 돈(수익 귀속)과 연결된다. 남의 노드를 흉내 내거나 가짜 노드를 늘리는 것을 막아야 한다.
- 하드웨어 지문 원본(GPU UUID 등)은 서버에 저장하지 않는다(S10 '하지 말 것').
- S10 명세는 지문을 `HMAC(storeSalt, 원본)` 하나로 만들면서 '같은 지문이 다른 매장에 동시에 나타나면 알림'도 요구한다. 매장마다 솔트가 다르면 매장 간 비교가 불가능하다(모순).

## 결정
- **키**: 노드마다 에이전트가 ed25519 키쌍을 만든다. 개인키는 영구 폴더에(Windows는 DPAPI 머신 범위 + 추가 엔트로피, S22), 서버에는 공개키만.
- **인증**: `hello` → `auth.challenge`(일회용 nonce, 5초 만료) → `auth.prove`. 서명 대상 바이트는 정확히 `"binjari-auth-v1\n" + nonce + "\n" + nodeId + "\n" + protocolHash`(UTF-8). 앞의 도메인 문자열이 매니페스트 서명 등 다른 용도와 섞이지 않게 한다. nonce 재사용·만료·잘못된 서명은 `auth.fail` 후 종료(S11).
- **지문 두 개**(S10 명세 보완):
  - `fpStore = HMAC-SHA256(storeSalt, 원본)` — 같은 매장 안 재부착 판단용. `storeSalt`는 `enroll.start` 응답으로 받는다.
  - `fpGlobal = HMAC-SHA256(globalSalt, 원본)` — 매장 간 같은 하드웨어 탐지용. `globalSalt`는 서버 전체에 하나. GPU UUID는 128비트 난수라 솔트가 알려져도 원본을 역산할 수 없다(목적은 DB 유출 시 원본 노출 방지).
  - 원본: GPU UUID 1순위, 시스템 UUID 보조(일부 메인보드는 기본 UUID가 같다). 서버로 보내지 않는다.
- **등록 코드**: `single`(PC 1대, 24시간) / `image`(매장 단위, 여러 번, 폐기 가능). 8자 base32(혼동 문자 제외), 해시로 저장, 시도 횟수 제한.
- **재부착**: `image` 코드로 같은 매장에 같은 `fpStore`의 노드가 있으면 새 노드를 만들지 않고 공개키만 바꿔 묶는다. 조건: 그 노드가 **지금 연결되어 있지 않을 것**(연결 중인데 같은 지문으로 재부착을 시도하면 복제 의심 → 격리). 재부착은 감사 기록·속도 제한·사장님 화면 이력.
- **복제 탐지(서버)**: 같은 공개키 + 다른 지문, 또는 같은 노드로 동시에 두 연결 인증 → 두 쪽 모두 격리 + 재등록 요구 + 알림(단, 재개 토큰을 가진 재연결은 정상 처리하고 옛 연결을 닫는다). 같은 `fpGlobal`이 다른 매장에 동시에 나타나면 운영자 알림(PC 이동인지 부정인지 사람이 판단).
- **복제 탐지(에이전트)**: 저장된 신원과 함께 저장한 지문이 현재 하드웨어 지문과 다르면 그 신원은 복제본이다 → 폐기하고 재등록(S20). 서버 쪽과 함께 이중 방어.
- **영구 폴더가 없는 PC**: 매 부팅 새 키를 만들고 이미지 코드로 재부착한다. `single` 코드는 한 번만 쓰이므로 이런 PC에는 맞지 않다 → 설치 프로그램(S21)이 영구성 점검(S20) 결과에 따라 이미지 코드를 요구한다.
- **이미지 코드 보호**: 이미지 코드는 PC 디스크(설정)에 있으므로 손님이 읽을 수 있다고 가정한다. 영구 폴더 ACL로 사용자 읽기를 막고(S22), 이미지 코드로 새로 생기는 노드는 매장 설정에 따라 사장님 승인 대기(`pending`)로 둘 수 있다. 재부착은 같은 매장·같은 지문으로만 가능하므로 다른 PC를 빼앗지 못한다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| 공유 비밀(API 키)로 노드 인증 | 단순 | 유출되면 재사용, 복제 구분 불가 | 개발용으로만(S04 → S11에서 제거) |
| mTLS 클라이언트 인증서 | 표준 | 인증서 발급·갱신 운영, 프록시 환경에서 TLS 종료 문제 | 1인 운영 부담 |
| TPM 기반 키 | 복제 불가 | PC방 PC의 TPM 유무·상태 모름, 복원 솔루션과 충돌 가능 | KNOWN_UNKNOWNS. 나중 강화 후보 |
| 지문 하나(매장 솔트) | 명세 그대로 | 매장 간 탐지 불가 | 위 모순 |
| 지문 원본을 서버에 저장 | 비교 쉬움 | 개인정보·하드웨어 식별자 유출 위험 | S10 '하지 말 것' |

## 결과와 트레이드오프
- 쉬워지는 것: 재부팅으로 초기화되는 PC도 같은 노드로 돌아온다(수익·평판 연속). 이미지 복제는 서버·에이전트 양쪽에서 잡힌다.
- 어려워지는 것: GPU를 교체하면 지문이 바뀌어 새 노드가 된다(사장님 화면에서 '교체'로 합치는 기능은 v0.1 범위 밖, 운영자 처리).
- VM이나 GPU 패스스루로 가짜 하드웨어를 만드는 공격은 지문만으로 못 막는다 → 검증(ADR 0007)과 승인 대기로 막는다.

## 재검토 조건
- 파일럿에서 지문 충돌(서로 다른 PC가 같은 GPU UUID를 보고) 사례가 나올 때.
- 재부착 빈도가 하루 노드당 1회를 크게 넘을 때(영구 폴더 없는 매장이 많다는 뜻 — 설치 방식 재검토).
- TPM이 대부분 매장에서 쓸 수 있다고 확인될 때.
