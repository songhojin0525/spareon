# 0011. 에이전트는 Windows 서비스 + 사용자 세션 헬퍼로 나누고, 손님 입력은 `GetLastInputInfo` 폴링으로만 본다

- 상태: 채택
- 날짜: 2026-10-08
- 차수: S01

## 맥락
- 에이전트는 PC가 켜져 있는 동안 사용자 로그인과 무관하게 돌아야 하고, 재시작에도 살아나야 한다 → Windows 서비스.
- Windows 서비스는 세션 0에서 돌아 사용자 세션의 입력·화면을 볼 수 없다(세션 0 격리).
- 손님이 앉았는지 빠르고 확실하게 알아야 한다(입력 → 프로세스 종료 0.5초, ADR 0016).
- PC방 PC에는 게임 안티치트와 백신이 돈다. 키로거처럼 보이는 동작은 차단·경고·평판 손상을 부른다. 손님의 사생활 측면에서도 입력 '내용'을 볼 이유가 없다.

## 결정
- **서비스(`binjari-agent`, 세션 0)**: 연결·작업 실행·런타임·다운로드·업데이트·적격 판정을 맡는다. 실행 계정은 S22 ADR에서 최소 권한으로 정한다.
- **헬퍼(`binjari-helper`, 사용자 세션, 사용자 권한)**: 서비스가 세션 변경 알림(`SERVICE_CONTROL_SESSIONCHANGE`)을 받아 활성 대화형 세션마다 `WTSQueryUserToken` + `CreateProcessAsUser`로 띄운다. 죽으면 백오프로 다시 띄운다. 대체 경로: 작업 스케줄러 '로그온 시 실행'(서비스 방식이 실패하는 환경용, S18).
- **헬퍼가 보는 것**: `GetLastInputInfo`를 100ms마다 폴링해 '마지막 입력 이후 경과 시간'과 '새 입력이 생긴 순간'만 본다. 앞 창 프로세스 이름, 전체 화면 여부, 세션 ID를 함께 보낸다. 입력 내용·화면 내용은 보지 않는다.
- **IPC**: 이름 있는 파이프 `\\.\pipe\binjari-presence`. ACL: 인증된 사용자 쓰기, 서비스 읽기. 서비스는 파이프 클라이언트 PID를 조회해 자기가 띄운 헬퍼인지 확인한다(가짜 '유휴' 신호 방지). 메시지 크기 상한·형식 검증.
- **신호 방향**: 헬퍼는 새 입력을 감지하면 폴링 주기를 기다리지 않고 즉시 보낸다. 평소에는 100~250ms마다 상태와 하트비트를 보낸다. 서비스는 헬퍼 하트비트가 1초 넘게 없으면 '헬퍼 없음' → 작업 불가(fail-safe).
- **금지**: 저수준 키보드·마우스 훅(`SetWindowsHookEx` `WH_KEYBOARD_LL`/`WH_MOUSE_LL`), 화면 캡처, 키 입력 내용 수집, PC방 관리 프로그램 역공학(S18 '하지 말 것').
- **런타임 위치**: 기본은 서비스가 런타임을 Job Object에 넣어 실행한다. 세션 0에서 CUDA가 동작하지 않으면(KNOWN_UNKNOWNS) 사용자 세션에서 제한된 런타임을 띄우는 대안을 S22 ADR에서 정한다. 이 대안에서도 선점 경로(종료 권한)는 서비스가 가져야 한다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| 저수준 입력 훅 | 입력 즉시 이벤트, 폴링 지연 없음 | 키로거 패턴 → 백신·안티치트 탐지·차단, 게임 입력 지연 위험, 사생활 | 사업 신뢰(사장님·손님)에 치명적 |
| Raw Input API 등록 | 훅보다 덜 침습적 | 창이 있어야 하고 앞 창에만 전달되는 등 제약, 역시 입력 스트림을 받는다 | 필요 이상 |
| 서비스만(헬퍼 없음) | 단순 | 세션 0에서는 사용자 입력 시각을 알 수 없다 | 불가능 |
| 사용자 세션 앱만(서비스 없음) | 단순 | 로그온 전·로그아웃 시 동작 불가, 손님이 쉽게 종료, 재시작 보장 약함 | 운영 안정성 |
| PC방 관리 프로그램 연동만 | 손님 로그인 정확 | 표준 방법 없음, 제품마다 다름 | 꽂을 수 있는 자리만 남긴다(S18) |

## 결과와 트레이드오프
- 쉬워지는 것: 백신·안티치트와 충돌 가능성이 낮다. 손님 사생활 설명이 쉽다("입력이 있었는지 시각만 본다").
- 어려워지는 것: 폴링 때문에 감지 지연이 최대 100ms 생긴다(0.5초 예산 안). 프로세스가 둘이라 배포·감시·IPC 보안이 필요하다.
- 입력 없이 화면만 보는 손님(영상 시청 등)은 입력 신호로 못 잡는다 → 전체 화면·GPU 사용·오디오 재생 신호를 함께 쓴다([ARCHITECTURE 자기 반박](../ARCHITECTURE.md#11-자기-반박-가정이-틀리면)).

## 재검토 조건
- 실기(S18 수동 체크리스트)에서 입력 → 프로세스 종료가 0.5초를 자주 넘을 때.
- 안티치트가 헬퍼의 `GetLastInputInfo` 폴링이나 파이프를 문제 삼는 사례가 나올 때.
- PC방 관리 프로그램 회사와 제휴해(BUSINESS_CONTEXT 7절 영업 3번) 손님 로그인 신호를 공식으로 받을 수 있게 될 때.
