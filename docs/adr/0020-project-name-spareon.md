# 0020. 프로젝트 이름은 spareon(Spareon)이다

- 상태: 채택
- 날짜: 2026-10-10
- 차수: S04(진행 중에 사람의 결정으로 끼워 넣음)

## 맥락
- `binjari`(빈자리)는 처음부터 가칭 코드네임이었다(CLAUDE.md). 사람이 정식 이름을 `spareon`으로 정했다(2026-10-10).
- 아직 배포한 적이 없다. 운영 DB, 설치된 에이전트, 서명된 배포본, 외부에 공개한 API가 하나도 없다. 그래서 프로토콜 상수와 마이그레이션까지 한 번에 바꿔도 깨지는 사용자가 없다.

## 결정
1. 모든 이름을 바꾼다. 패키지 `@spareon/*`, Go 모듈 `spareon/agent`, 실행 파일 `spareon-agent`·`spareon-helper`·`spareon-updater`, DB 역할 `spareon_app`·스키마 `spareon_meta`·함수 접두사 `spareon_`, 환경변수 `SPAREON_*`.
2. 한국어 문서와 화면에서도 서비스 이름은 `Spareon`(영문 그대로)이다. '빈자리'는 쓰지 않는다.
3. 서명 도메인 문자열(`spareon-auth-v1`, `spareon-enroll-v1`, `spareon-<kind>-manifest-v1`)과 매니페스트 스키마 이름(`spareon.model-manifest/1` 등)도 바꾼다. `packages/protocol/fixtures/vectors/signatures.json`은 같은 키로 다시 서명해 만들었다. 일부러 깨뜨린 사례(비트 뒤집기, S + L, 대문자, 잘린 서명)도 같은 변형을 새 서명에 적용했다. 개발용 신원 벡터는 생성 스크립트로 다시 만들었다.
4. 마이그레이션 0000~0003은 새 마이그레이션을 추가하지 않고 그대로 고쳤다. 어떤 운영 DB에도 적용된 적이 없기 때문이다(0003 때와 같은 근거, ADR 0018).
5. 예외: `packages/testkit/test/random.test.ts`의 시드 문자열 `'binjari'`. 알고리즘이 바뀌지 않았는지 확인하는 고정 정답값이 이 입력으로 계산되어 있다. 정답값을 새 입력으로 다시 계산하면 검사 대상 코드로 정답을 만드는 셈이므로, 입력만 그대로 둔다.
6. 브랜드 표기: 워드마크는 `Spareon`(S만 대문자)이고, 전원 버튼과 S를 겹친 심볼을 함께 쓴다. 어두운 배경에서는 `Spare`를 #F3F6F2, `on`과 전원 막대를 브랜드 초록 #14B86A로 쓴다. 밝은 배경에서는 #0E1A15와 #0A8A4E를 쓴다. 자산 파일과 사용 규칙은 `docs/brand/README.md`에 있다. 진행 보드·상태줄에 적용했고, 웹(S23)의 디자인 토큰도 이 값에서 출발한다.
   - 개정(2026-10-10): 처음에는 소문자 `spareon`과 청록(#2DD4BF·#0D9488)으로 정했다. 같은 날 사람이 로고 시안(심볼 + `Spareon` + 초록)을 내놓아 그 시안을 다듬어 정식 자산으로 삼고 위 값으로 바꿨다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| 화면 이름만 바꾸고 코드 식별자는 binjari 유지 | 변경이 작다 | 코드·문서·화면 이름이 영원히 갈린다. 문서와 코드가 같아야 한다는 절대 규칙 8의 정신에도 어긋난다 | 배포 전이라 지금이 가장 싸다 |
| 서명 도메인 문자열은 그대로 두기 | 서명 벡터를 다시 만들 필요가 없다 | 프로토콜 안에 옛 이름이 남는다 | 배포 전이고 재서명을 자동화할 수 있다 |
| 새 마이그레이션 0004로 역할·스키마 이름 바꾸기 | 체크섬 기록 보존 | 적용된 DB가 없는데 복잡도만 는다 | ADR 0018의 '배포 전에는 고쳐 쓴다' 근거와 같다 |

## 결과와 트레이드오프
- 쉬워지는 것: 이름이 하나로 통일된다.
- 남는 일(사람): 저장소 폴더 `C:\binjari` → `C:\spareon`, GitHub 저장소 이름 바꾸기(HUMAN_TODO). 폴더를 바꾸면 Claude Code 프로젝트 기록(메모리)의 경로도 바뀐다.
- 옛 커밋 메시지와 태그 메시지에는 binjari가 그대로 남는다(히스토리 재작성 금지, 절대 규칙 6).

## 재검토 조건
- 상표·도메인 확인에서 `spareon`을 쓸 수 없다고 나올 때. 그때도 지금과 같은 방법으로 다시 바꿀 수 있다(배포 뒤라면 프로토콜 도메인 v2와 새 마이그레이션이 필요하다).
