# 0014. 1 크레딧은 기본으로 1달러에 고정하고, 바스켓 페그는 실험 플래그로 잠근다

- 상태: 채택
- 날짜: 2026-10-08
- 차수: S01

## 맥락
- 1크레딧을 무엇에 묶을지는 미결정이다(BUSINESS_CONTEXT 5절, 12절). 달러 고정은 안정적이지만 사실상 선불 충전금이고, 여러 모델 가격의 평균(바스켓)은 'AI 화폐'에 가깝지만 AI 값이 내려가면 크레딧의 달러 가치도 내려간다.
- 코드는 둘 다 지원하되 기본은 달러 고정이다(BUSINESS_CONTEXT 5절).
- 준비금은 원화로 받는다. 외부 모델 원가는 달러다. 부채(크레딧)는 페그 기준 통화(달러)로 표시된다 → 환율 위험이 생긴다.

## 결정
- `PegPolicy` 인터페이스(S08):
  - `UsdFixed`(기본): 1 CR = 설정값 µUSD(기본 1,000,000 = 1달러).
  - `Basket`(실험): 참조 모델 가격 지수로 1 CR의 가치를 매일 스냅숏. 기능 플래그 `peg_basket`이 꺼져 있으면 API·CLI 접근도 거부.
- 페그 값과 환율(`fx_rates`)은 거래마다 스냅숏 ID로 남긴다. 환율이 7일(설정)보다 오래되면 외부 환전과 테스트 충전을 막는다(`fx_stale`).
- **준비금 가드의 부채 정의**(S08 명세 보완, [ARCHITECTURE 이견 절](../ARCHITECTURE.md#12-이견-명세와-다르게-설계한-것)): 부채 = 구매자 CR(지갑 + 홀드) + 매장 CR 수익(미성숙 + 보류 + 확정 + 정산 처리 중). 모두 페그·환율로 달러 환산. 준비금 = 준비금 계정(KRW)의 달러 환산. 외부 환전은 `(준비금 − 미정산 예약 합 − 이번 예약) / 부채 ≥ reserveMinRatio`일 때만(ARCHITECTURE 9.4와 같은 식). TCR은 부채·준비금 어느 쪽에도 넣지 않는다(실제 돈이 아님).
- 환율 변동만으로 비율이 기준 밑으로 내려갈 수 있다(원화 약세). 이때 가드는 외부 환전을 막는다(fail-safe). 완충을 위해 `reserveMinRatio` 기본값은 S07이 환율 변동 시나리오로 정한다(1.0보다 클 수 있다).

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| 원화 고정(1 CR = N원) | 환율 위험 없음, 사장님·구매자에게 직관적 | 외부 모델 원가가 달러라 환전율이 환율 따라 매일 바뀐다, 해외 구매자에게 낯섦 | 사업 문서가 달러 기준 환율표를 전제 |
| 바스켓 기본 | 비전에 가까움 | AI 가격 하락 시 보유자 구매력·신뢰 하락, 설명 어려움 | 미결정 사항을 기본값으로 정하지 않는다 |
| 부채를 구매자 크레딧만으로 정의(S08 명세 그대로) | 단순 | 캡처 뒤 사장님에게 줄 돈이 부채에서 빠져, 그 돈을 외부 환전에 써 버릴 수 있다 | 돈 구멍 |

## 결과와 트레이드오프
- 쉬워지는 것: 가격표·환율표를 달러 기준으로 설명할 수 있다(BUSINESS_CONTEXT 3절 표 그대로).
- 어려워지는 것: 원화 준비금 ↔ 달러 부채 사이 환율 위험을 플랫폼이 진다. 환율 입력은 운영자가 수동으로 한다(자동 수집은 v0.1 범위 밖).
- 바스켓을 켜면 기존 보유자의 구매력이 바뀐다 → 켜는 것은 새 ADR과 공지가 필요한 결정.

## 재검토 조건
- BUSINESS_CONTEXT 12절 '1크레딧을 달러에 묶을까' 질문이 결정될 때.
- 원화 대비 달러가 한 달에 5% 넘게 움직여 가드가 외부 환전을 자주 막을 때(준비금 일부를 달러로 보유하는 방안).
- 실제 결제가 시작되어 준비금이 실제 돈이 될 때(로드맵 2단계).
