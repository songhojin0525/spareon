# 0013. 크레딧 발행은 마켓플레이스 방식(구매자 지불이 보상의 원천)이 기본이고, 발행형(난이도 조절)은 시뮬레이션 전용이다

- 상태: 채택
- 날짜: 2026-10-08
- 차수: S01

## 맥락
- 비트코인은 사는 사람이 없어도 프로토콜이 새 코인을 찍어 보상한다. AI 연산은 실제로 사 주는 구매자가 있어야 가치가 있다. 코인으로 보상하면 가치가 시세에 묶인다(BUSINESS_CONTEXT 4절 2번).
- 장기 비전은 '연산이 크레딧을 만든다'(채굴)이고, 가치 유지를 위해 난이도 조절이 필요하다(5절). 하지만 지금 새 크레딧을 발행하면 준비금 없는 부채가 생기고, 법적으로도 위험하다(ADR 0006).

## 결정
- **마켓플레이스 방식(기본, 유일한 운영 모드)**: 매장 수익(노드 몫)은 구매자가 낸 작업 비용에서만 나온다(`JOB_CAPTURE`의 분할). 플랫폼이 부담하는 검증 작업 비용(`VERIFICATION_COST`)만 예외이고, 이것도 같은 통화의 플랫폼 매출(이미 들어온 돈)에서 작업 생성 시 예약해 지급한다(음수 허용 계정 없음, ARCHITECTURE 12절 D22). 원장에 '무에서 크레딧을 만드는' 거래 종류는 운영자 `TEST_TOPUP`(실제 자금 기록)과 샌드박스 `TCR` 충전뿐이다.
- **발행형(난이도 조절)**: `tools/econ-sim`(S07)에서만 모델링한다. 서버 코드에는 발행형 경로를 만들지 않는다. 설정 `issuanceMode`는 `marketplace`만 허용하고 다른 값이면 시작 거부.
- 사장님 화면·영업 문구에서 '채굴'은 비유로만 쓰고, 실제로는 "손님 없는 시간에 판 연산의 몫"이라고 정직하게 설명한다(S24, S31).

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| 발행형을 플래그로 잠가 서버에 구현 | 실험 전환 쉬움 | 준비금 없는 크레딧 발행 경로가 코드에 생긴다, 법적 위험 | 돈이 생기는 경로를 만들지 않는다 |
| 혼합(구매자 지불 + 소량 발행 보너스) | 초기 공급자 유인 | 부채 증가, 회계 복잡 | 보너스가 필요하면 플랫폼 매출에서 '프로모션 비용' 거래로 지급(새 ADR) |
| 수요가 없을 때 노드에 '대기 보상' | 사장님 만족 | 실체 없는 지급 → 플랫폼 손실 | 사업 지속 불가 |

## 결과와 트레이드오프
- 쉬워지는 것: 모든 크레딧이 실제 돈(또는 명시적 테스트 기록)에 뒷받침된다. 준비금 가드(ADR 0014, S08)가 의미를 가진다.
- 어려워지는 것: 구매자가 없으면 매장 수익도 없다. 파일럿 초기에는 창업자 자금(`TEST_TOPUP`)과 부하 생성기(`tools/loadgen`)로 수요를 만든다. 사장님께는 이 사실을 숨기지 않는다.
- '컴퓨팅 본위 화폐' 비전과의 간극은 문서(BUSINESS_CONTEXT 11절 로드맵)로 관리한다.

## 재검토 조건
- 토큰 발행이 합법화되고(로드맵 3단계 조건) 준비금 체계가 안정될 때.
- S07 시뮬레이션에서 발행형이 마켓플레이스보다 사장님 수익 안정성·플랫폼 부채 모두에서 낫다는 결과가 나올 때.
