# 0002. 작업 큐는 별도 브로커 없이 Postgres로 만든다 (`FOR UPDATE SKIP LOCKED` + `LISTEN/NOTIFY`)

- 상태: 채택
- 날짜: 2026-10-08
- 차수: S01

## 맥락
- 작업(job)·시도(attempt)·홀드·수익은 한 트랜잭션 안에서 함께 바뀌어야 한다. 예: "시도 완료 + 작업 완료 + 홀드 캡처 + 미성숙 수익 생성"이 따로 커밋되면 이중 과금이나 잃어버린 작업이 생긴다(CLAUDE.md 절대 규칙 3).
- 1인 운영·저비용(BUSINESS_CONTEXT 13절 6번). 운영할 상태 저장소가 하나 늘 때마다 백업·감시·장애 대응이 늘어난다.
- 규모 목표: 초기 300노드, 설계 목표 3만 동시 연결([ARCHITECTURE 규모 절](../ARCHITECTURE.md#8-규모-가정과-확장-경로)). 작업 처리량은 노드 수 × (1 / 평균 작업 시간)이고, 3만 노드 × 30초 작업이면 초당 1,000건 완료다.
- 운영 DB는 관리형 Postgres(예: Supabase)일 수 있다. 연결 풀러의 트랜잭션 모드에서는 `LISTEN`이 동작하지 않는다(S30에서 연결 분리).

## 결정
- 큐는 Postgres 테이블(`jobs`, `job_attempts`)이다. 꺼낼 때 `SELECT … FOR UPDATE SKIP LOCKED LIMIT n`을 쓰고, 상태 전이는 `UPDATE … WHERE id = $1 AND status = $expected`처럼 조건부로 한다. 영향 행 수가 0이면 경합에서 진 것이다.
- 새 작업, 노드가 대기 상태로 바뀜, 킬스위치 같은 사건은 같은 트랜잭션에서 `outbox_events`에 쓰고, 커밋 뒤 `NOTIFY`로 깨운다. 폴링(기본 1초)은 놓친 알림을 줍는 보조 수단이다.
- `LISTEN`은 전용 직접 연결 하나로 받는다(`DATABASE_LISTEN_URL`, S30). 일반 쿼리는 풀을 쓴다.
- 다중 인스턴스 단계에서는 스케줄러 리더 하나를 Postgres advisory lock으로 뽑는다. 게이트웨이는 여러 개가 될 수 있고, 다른 인스턴스에 붙은 노드로 가는 명령은 `NOTIFY`로 전달한다(S11).

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| Redis(+BullMQ 등) | 빠름, 생태계 | 상태 저장소가 둘. 큐와 원장이 한 트랜잭션에 묶이지 않아 아웃박스·보상 로직이 필요 | 돈과 작업 상태의 원자성을 잃는다. 운영 대상이 하나 늘어난다 |
| RabbitMQ / NATS JetStream | 전달 보장, 라우팅 | 운영 부담, 관리형은 비용. 역시 DB와 별도 트랜잭션 | 1인 운영에 과함 |
| pg-boss·graphile-worker 같은 Postgres 큐 라이브러리 | 바로 사용 | 우리 작업 모델(오퍼·리스·선점·이어쓰기)은 일반 작업 큐와 다르다. 결국 상태 기계를 따로 들게 된다 | 이득이 작다. 필요한 부분(SKIP LOCKED, NOTIFY)은 몇 줄이다 |
| 메모리 큐(단일 프로세스) | 가장 단순 | 재시작하면 작업을 잃는다 | 절대 규칙 3과 S15(재시작 후 이어서 완료) 위반 |

## 결과와 트레이드오프
- 쉬워지는 것: 작업 상태와 원장이 한 트랜잭션. 백업 하나로 전부 복구. 테스트는 embedded-postgres로 실제와 같게 돈다.
- 어려워지는 것: DB가 큐 부하까지 받는다. 하트비트·리스 갱신을 행 단위로 매번 쓰면 3만 노드에서 초당 수천 건 쓰기다 → 리스 갱신은 메모리에서 하고 DB에는 모아서 쓴다([ARCHITECTURE 규모 절](../ARCHITECTURE.md#8-규모-가정과-확장-경로)).
- `NOTIFY` 페이로드는 8000바이트 제한이 있다 → ID만 보내고 내용은 DB에서 읽는다.
- 되돌리는 비용: 큐 접근을 `scheduler/queue` 모듈 하나로 모아 두면, 나중에 브로커로 옮길 때 그 모듈만 바꾸면 된다.

## 재검토 조건
- 단일 Postgres에서 작업 완료 처리량이 목표(S12 측정)의 절반 아래로 떨어지거나, 큐 테이블 때문에 원장 쿼리 p95가 2배 넘게 나빠질 때.
- 관리형 Postgres의 직접 연결 수 제한 때문에 `LISTEN` 연결을 유지할 수 없을 때.
