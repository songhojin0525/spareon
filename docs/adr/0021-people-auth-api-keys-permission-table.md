# 0021. 사람은 서버 저장 세션 + 세션에 묶인 CSRF 토큰, 구매자는 HMAC으로 저장한 `sp_test_` API 키, 권한은 문서 표가 원본

- 상태: 채택
- 날짜: 2026-10-10
- 차수: S05

## 맥락
- 사장님·구매자·운영자 화면은 사람 로그인을 쓰고(ADR 0012: 같은 출처 프록시, 쿠키), 구매자 프로그램은 OpenAI SDK로 `/v1/*`를 API 키로 부른다.
- 위협: 자격 증명 대입(WEB-01), CSRF(WEB-02), IDOR(WEB-04, BUY-06), 세션 고정(WEB-05), 계정 열거(WEB-07), 유출된 API 키(BUY-01), DB 유출(DATA-01), 로그 누출(DATA-06). 1인 운영이라 외부 인증 서비스·Redis 없이 Postgres 하나로 끝나야 한다.
- 키 형식과 쿠키 이름은 구매자 코드·브라우저에 퍼지므로 나중에 바꾸기 어렵다.

## 결정
1. **비밀번호**: argon2id(m=19,456 KiB, t=2, p=1 — OWASP Password Storage Cheat Sheet 최소 권장, 2026-10-10 확인), 12~256자. `@node-rs/argon2`.
2. **세션**: 32바이트 무작위 토큰을 httpOnly·SameSite=Lax 쿠키로(https면 Secure + `__Host-` 접두사), DB에는 SHA-256만. 유휴 7일·절대 30일(설정 가능). 로그인 때 언제나 새 토큰을 만들고 들고 온 세션은 폐기. 로그아웃·비밀번호 재설정·계정 비활성화는 서버에서 즉시 폐기.
3. **CSRF**: 상태를 바꾸는 쿠키 요청은 Origin(없으면 Referer) = `WEB_ORIGIN` **그리고** `x-csrf-token` = CSRF 쿠키. 로그인 상태면 토큰은 `HMAC(SESSION_SECRET 유도 키, 세션 토큰 해시)`여야 한다(쿠키 주입으로 쌍을 바꿔치기할 수 없음).
4. **로그인 실패**: 한 가지 메시지, 없는·비활성·시드 계정도 더미 해시로 argon2 1회, 실패 응답은 최소 400ms. 계정(어떤 이메일이든)별 실패 5회/15분 잠금, IP별 시도 30회/15분. 가입은 있는 이메일에도 같은 202 응답이고 자동 로그인하지 않는다.
5. **API 키**: `sp_test_<8 base62>_<32 base62>`. 표시·조회용 prefix `sp_test_<8>`, 저장은 `HMAC-SHA256(API_KEY_PEPPER, 키)`와 pepper ID. 조회는 해시로(앱에서 비밀 비교 없음). 스코프 `chat`·`batch`·`models:read`, 키별 분당 한도(열)와 키별 동시 한도(설정). 차수 문서의 `bj_` 접두사는 옛 이름이라 ADR 0020에 따라 `sp_`.
6. **권한**: `docs/PERMISSIONS.md`의 역할 × 동작 표가 원본이고 `http/permissions.ts`가 같은 표다. 라우트는 `Router.add({ action })`로만 등록되고 인증·표 적용·CSRF·입력 검증·키 한도는 래퍼가 한다. `자기 것`은 쿼리에 소유권 조건, 남의 것은 404. 테스트가 문서 표를 읽어 모든 행 × 역할을 HTTP로 실행하고 등록된 라우트를 표와 대조한다.
7. **속도 제한 저장소**는 인터페이스(`RateLimiter`)와 메모리 구현. 단일 인스턴스(ADR 0002 단계 A)라 충분하다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| JWT(무상태) | DB 조회 없음 | 폐기·비활성화가 어렵고 XSS로 탈취 | ADR 0012에서 이미 버림 |
| 서명된 쿠키 세션 | 저장소 없음 | 서버 쪽 즉시 폐기 불가 | 계정 비활성화·로그아웃 보장 |
| 세션에 묶지 않은 이중 제출 CSRF | 단순 | 하위 도메인 등에서 쿠키를 심으면 쌍을 맞출 수 있다 | 세션 결합 HMAC 한 줄로 막힘 |
| API 키를 bcrypt/argon2로 저장 | 느린 해시 | 요청마다 수십 ms, prefix로 찾은 뒤 비교 필요 | 키는 190비트 무작위라 느린 해시가 필요 없다 |
| 키를 prefix로 찾아 비밀 비교 | 일반적 | 비교 타이밍을 신경 써야 함 | HMAC으로 바로 찾으면 비교 자체가 없다 |
| 권한을 핸들러마다 `if` | 유연 | 빠뜨려도 아무도 모름 | 표 + 래퍼 + 자동 대조 테스트 |
| 외부 인증 서비스(Auth0 등) | 기능 많음 | 비용·의존·한국어 UI·데이터 이전 | 1인 저비용 |

## 결과와 트레이드오프
- 쉬워지는 것: 새 라우트는 표에 행을 더하고 탐침 하나만 쓰면 권한 테스트가 생긴다. DB 유출로 세션·API 키를 쓸 수 없다.
- 어려워지는 것: 메모리 속도 제한은 재시작하면 지워지고 여러 인스턴스에서 공유되지 않는다(로그인 잠금이 풀림). 이메일 확인이 없어서 '가입 → 그 비밀번호로 로그인'으로 계정 존재를 알아낼 수 있다(WEB-07 잔여 위험, 이메일 발송은 v0.1 밖). `API_KEY_PEPPER`를 잃으면 모든 키가 무효다(pepper ID로 회전은 가능하나 회전 절차는 S29·S30).
- 되돌리는 비용: 키 형식·쿠키 이름은 배포 뒤에는 바꾸기 비싸다(지금은 배포 전).

## 재검토 조건
- 서버 인스턴스가 둘 이상이 될 때(속도 제한을 Postgres·Redis 저장소로).
- 이메일 발송이 생길 때(가입 확인 메일로 WEB-07 잔여 위험 제거, 비밀번호 재설정 메일).
- 운영자 2단계 인증(TOTP) 도입 때(S28) 또는 OWASP 권장 파라미터가 바뀔 때.
