# 0009. 과금용 토큰 수는 서버가 센다 — 노드 보고값은 교차 검증용이다

- 상태: 채택
- 날짜: 2026-10-08
- 차수: S01

## 맥락
- 노드는 신뢰할 수 없다. 노드가 보고하는 토큰 수를 그대로 과금에 쓰면 부풀리기로 구매자에게서 돈을 빼 가고 자기 몫을 늘릴 수 있다.
- 구매자도 사용량(usage)을 확인할 수 있어야 한다. OpenAI 호환 API는 `usage.prompt_tokens`, `completion_tokens`를 돌려준다(S14).
- 토크나이저는 모델마다 다르다. 서버는 모델별 토크나이저와 대화 템플릿을 가져야 한다(S09).

## 결정
- 입력 토큰: 서버가 모델의 대화 템플릿을 적용한 뒤 모델 토크나이저로 센다. 견적(홀드)과 과금 모두 이 값.
- 출력 토큰: 노드가 돌려준 출력 텍스트(스트리밍이면 구매자에게 실제로 전달된 텍스트)를 서버가 다시 토큰화해 센다.
- 비용 = 가격표 버전(작업 생성 시 고정)으로 계산, 홀드를 넘지 않는다(ADR 0005).
- 노드 보고값(`reportedTokensIn/Out`)은 기록하고, 서버 값과 5%(설정) 넘게 다르면 검증 대상으로 표시한다(ADR 0007).
- 이어쓰기에서 두 번째 노드가 처리하는 접두사(앞 노드의 출력)는 구매자에게 다시 과금하지 않는다. 구매자는 원래 입력 1회 + 전달된 출력만 낸다. 접두사 재처리 비용은 플랫폼 부담이다.
- 서버 토크나이저가 없는 모델은 활성화할 수 없다(S09 활성화 게이트). S09 이전에는 보수적 추정(`SKELETON(S09)`).

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| 노드 보고값으로 과금 | 구현 쉬움, 런타임 값과 정확히 일치 | 부풀리기 공격 | 신뢰 경계 위반 |
| 글자 수·바이트 기준 과금 | 토크나이저 불필요 | 업계 관행(토큰)과 달라 구매자 비교가 어렵다, 언어별 불공평 | 가격 비교성 |
| 두 노드 보고값의 최솟값 | 서버 계산 없음 | 모든 작업 2중 실행 필요 | 비용 |

## 결과와 트레이드오프
- 쉬워지는 것: 과금 근거가 서버에 있어 노드 조작과 무관하다. usage가 원장 과금과 정확히 일치한다(S14 수용 기준 2).
- 어려워지는 것: 서버가 모델별 토크나이저를 들고 있어야 한다(메모리·CPU). 출력 재토큰화는 런타임이 실제로 만든 토큰 수와 조금 다를 수 있다(비정규 토큰화) → 차이는 작고, 홀드를 넘지 않게 상한을 둔다.
- 템플릿이 런타임과 다르면 입력 토큰이 어긋난다 → 고정 버전의 템플릿을 모델 매니페스트에 함께 서명해 배포한다(S09).

## 재검토 조건
- 서버 토큰화 CPU가 요청 처리 시간 p95의 20%를 넘을 때(캐시·별도 워커 검토).
- 노드 보고값과 서버 값의 차이가 성실 노드에서도 5%를 자주 넘을 때(템플릿 불일치 의심 → 기준 재조정).
