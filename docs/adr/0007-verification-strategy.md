# 0007. 검증은 카나리아 + 다른 매장 중복 실행 + 모델 지문 + 평판 + 성숙 기간 + 회수의 겹으로 한다

- 상태: 채택
- 날짜: 2026-10-08
- 차수: S01

## 맥락
- AI 연산은 결과가 맞는지 즉시 확인할 수 없다. 노드가 더 싼 모델로 대충 답하거나, 아무 글자나 내보내거나, 예전 출력을 재사용하고 돈만 받을 수 있다(BUSINESS_CONTEXT 4절 1번).
- GPU가 다르면 그리디(temperature 0) 출력도 몇 토큰 뒤부터 갈라질 수 있다(KNOWN_UNKNOWNS). 너무 엄격하면 성실한 매장이 억울하게 격리된다.
- 검증 비용은 플랫폼이 부담한다. 목표: 전체 연산의 10% 이하(S13).
- 노드 수익은 성숙 기간 뒤 확정되고, 부정이 밝혀지면 회수한다(BUSINESS_CONTEXT 13절 4번).

## 결정
1. **카나리아**: 신뢰 노드(운영자가 지정)에서 미리 만든 정답이 있는 작업. 노드별 하루 일정 횟수, 실제 작업 분포에서 표본으로 뽑은 형태·길이·시간대로 섞는다. 프롬프트는 합성 말뭉치에서 만들고(구매자 데이터 재사용 금지), 같은 카나리아의 노출 횟수를 세어 일정 횟수 뒤 폐기한다(노드끼리 해시를 공유해 알아보는 것 방지).
2. **다른 매장 중복 실행**: 일반 작업의 일정 비율을 **다른 매장의** 노드에서 같은 파라미터·같은 시드로 한 번 더 돌린다(같은 매장끼리 짜고 치기 방지). 결과는 버리고 비교 점수만 남긴다.
3. **모든 작업에 서버가 시드를 붙인다.** 구매자가 시드를 주지 않아도 서버가 정한다. 그래서 '그리디 작업만 검증 대상'이라는 신호가 생기지 않고, 중복 실행이 temperature > 0 작업에도 걸린다.
4. **오퍼에 검증 표시가 없다.** 검증 작업은 메시지 필드·크기 분포가 일반 작업과 같아야 한다(S02 명세의 `verification` 플래그는 넣지 않는다 — ADR 0003 보완).
5. **모델 지문**: 모델마다 출력이 확실히 갈리는 짧은 프롬프트 집합. 다른 모델로 바꿔치기한 노드를 잡는다. 카나리아 풀에 섞어 보낸다.
6. **토큰 수 교차 확인**: 노드 보고 토큰 수와 서버 계산이 5% 넘게 다르면 검증 대상으로 표시(ADR 0009).
7. **비교와 판정**: 앞 K토큰(기본 32) 완전 일치 + 전체 정규화 편집 거리로 점수화. 판정은 pass / fail / inconclusive. 중복 실행에서 둘이 다르면 제3 노드(가능하면 신뢰 노드)로 다수결. 한 번의 fail로 처벌하지 않고, 확정된 판정만 평판에 반영한다.
8. **평판**: 베타 분포 사후 평균(성공·실패 가중 누적, 시간 감쇠). 낮은 평판 = 더 자주 검증 + 매칭 점수 감점. 격리 기준: 7일 창 안 확정 실패 N회 또는 평판 임계 이하.
9. **성숙 기간과 보류**: 노드 몫은 미성숙 수익으로 쌓이고 기본 72시간 뒤 확정된다. 검증 판정 목표 시간(24시간)보다 길어야 한다. 노드가 격리·조사 중이면 그 노드의 미성숙 수익은 성숙하지 않고 `held`(보류)로 멈춘다.
10. **회수**: 확정된 부정에 연결된 미성숙·보류 수익은 `EARNING_CLAWBACK`으로 회수하고, 구매자에게는 재실행 또는 환불한다. 이미 성숙한 수익은 자동 회수하지 않고 운영자 검토 대기열로 올린다(S13 '하지 말 것').
- 검증 작업 비용(중복 실행하는 노드의 몫)은 `VERIFICATION_COST`로 플랫폼이 부담한다. 검증 비율 기본값은 S07 추천을 따른다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| 그리디 작업만 중복 실행 | GPU 간 비교가 가장 안정적 | 노드가 temperature 0 작업만 성실히 하고 나머지에서 속인다 | 검증 우회가 쉽다 |
| 교사 강제 로그확률 검사(검증 노드가 주장된 출력을 모델에 통과시켜 토큰별 확률이 그 모델에서 나올 만한지 확인) | GPU 비결정성에 강하다, 샘플링 작업에도 맞다 | 런타임에서 토큰별 로그확률을 받아야 하고 임계값 설계가 어렵다 | v0.1 기본은 아니지만 **대안 설계로 남긴다**. 시드 샘플링의 GPU 간 일치도가 낮게 나오면(S13 실측) 이것으로 바꾼다 |
| 신뢰 하드웨어(TEE)·원격 증명 | 강력 | 게임용 GPU·PC방 PC에서 불가 | 현실성 없음 |
| 모든 작업 2중 실행 | 가장 강함 | 비용 2배 | 10% 목표 위반 |
| 평판 없이 단발 판정으로 즉시 격리 | 단순 | 비결정성 오탐으로 성실 매장 격리 | 오탐 < 0.5% 목표 위반 |

## 결과와 트레이드오프
- 쉬워지는 것: 사기 유형마다 막는 겹이 있다(게으름·바꿔치기 → 지문·중복, 쓰레기 → 카나리아, 재사용 → 시드가 매번 다름, 토큰 부풀림 → 서버 계산).
- 어려워지는 것: 임계값이 GPU 비결정성 실측에 달려 있다. 성숙 기간 동안 사장님 수익이 '확정 대기'로 보인다(사장님 화면에 이유 설명, S24).
- 간헐적 사기(10%만 속임)는 탐지까지 오래 걸린다. 성숙 기간·회수로 피해를 묶는다.
- 성숙 후 정산이 이미 기록된 수익은 사실상 회수할 수 없다 → 정산 주기(수동, 월 단위 가정)가 성숙 기간보다 길어 실제 노출은 작다.

## 재검토 조건
- S13 적대적 시뮬레이션에서 목표(게으름·쓰레기·재사용 50작업 이내 탐지, 오탐 격리 < 0.5%, 검증 비용 ≤ 10%)를 못 맞출 때.
- 실기에서 같은 시드·같은 모델의 GPU 간 앞 32토큰 일치율이 90% 아래일 때(교사 강제 로그확률 검사로 전환).
- 파일럿에서 실제 부정 사례가 나올 때.
