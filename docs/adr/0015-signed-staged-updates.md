# 0015. 에이전트 업데이트는 서명 매니페스트 + 단계적 배포 + 자동 롤백으로 한다

- 상태: 채택
- 날짜: 2026-10-08
- 차수: S01

## 맥락
- 수백~수천 대 PC에 손으로 다시 설치할 수 없다. 버그를 고치려면 원격 업데이트가 필요하다(S21).
- 업데이트 채널은 가장 위험한 공격 경로다. 여기를 빼앗기면 모든 PC방 PC에서 임의 코드가 실행된다(THREAT_MODEL 상위 위험).
- 잘못된 업데이트 하나가 전체 노드를 동시에 망가뜨릴 수 있다(크래시 루프, 손님 감지 회귀).
- 복원 솔루션 PC는 설치 폴더가 재부팅마다 되돌아간다(S20).

## 결정
- **서명**: 릴리스 매니페스트(버전, 파일 목록, SHA-256, 최소 호환 서버 버전, 대상 플랫폼)를 ed25519로 서명한다. 정규화 규칙(키 정렬·공백 없음·UTF-8)과 도메인 구분 문자열을 S02 테스트 벡터로 고정한다. 에이전트에는 릴리스 공개키(현재 + 다음 키)가 내장된다. 서명 개인키는 서버에 두지 않는다(오프라인 또는 사람의 기기, S28 KEY_MANAGEMENT).
- **검증 우회 금지**: 개발 모드에도 서명 검증을 끄는 옵션이 없다. 개발은 별도 개발 키로 서명한다(S21 '하지 말 것').
- **다운그레이드 금지**: 매니페스트 버전이 현재보다 낮으면 거부한다. 운영자가 명시한 롤백 매니페스트(서명됨, `rollbackOf` 표시)만 예외.
- **단계적 배포**: 비율(예: 1% → 10% → 50% → 100%)과 대상 매장(파일럿 먼저). 노드 선택은 `hash(nodeId, releaseId)` 기준으로 결정적. 매장별 버전 고정 가능.
- **건강 감시**: 새 버전 노드의 재연결 실패율·크래시 보고·작업 실패율·선점 지연 지표가 기준을 넘으면 배포를 자동 일시정지하고 운영자에게 알린다.
- **에이전트 쪽 롤백**: 별도 업데이터(`spareon-updater`)가 `versions/<버전>/`에 풀고 `current` 포인터를 바꾼다. 새 버전이 2분 안에 서버 인증에 성공하지 못하거나, 10분 안에 3번 크래시하면 이전 버전으로 되돌리고 보고한다. 이전 버전 1개를 보관한다.
- **설치 시점**: 손님 없음 + 작업 없음 + 다운로드 허용 시간대일 때만 받고 교체한다. 업데이트 때문에 PC를 재부팅하지 않는다.
- **복원 PC**: 실행 파일을 영구 드라이브의 버전 폴더에서 실행하는 구조를 기본으로 하고, 불가하면 "마스터 이미지 업데이트 필요"를 사장님·운영자에게 보고한다(S21 ADR에서 확정).

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| TLS로 받은 파일을 그대로 신뢰 | 단순 | 서버·저장소·CDN이 뚫리면 전체 PC 장악 | 신뢰 근거가 서명이어야 한다 |
| 전체 동시 배포 | 빠름 | 한 번의 실수가 전체 장애 | 1인 운영에서 복구 불가능한 사고 |
| Windows 기본 업데이트 도구(MSIX 자동 업데이트 등) | 표준 | 복원 솔루션·이미지 환경과의 상호작용 불명, 롤백 통제 어려움 | 통제권 |
| TUF(The Update Framework) 전체 도입 | 키 교체·위임·만료까지 표준화 | 구현·운영 복잡 | v0.1은 핵심 원칙(서명·버전 단조·키 교체 대비)만 차용. 재검토 조건에 둔다 |

## 결과와 트레이드오프
- 쉬워지는 것: 문제가 있는 릴리스의 피해가 처음 단계 비율로 묶인다. 서버가 뚫려도 서명 키 없이는 악성 업데이트를 못 보낸다.
- 어려워지는 것: 서명 키 보관·교체 절차가 사람에게 달려 있다(HUMAN_TODO). 긴급 수정도 단계를 거쳐야 한다(비율을 빠르게 올리는 것은 가능).
- 매니페스트 만료(재전송 공격으로 오래된 정상 릴리스를 계속 보여 주기)는 버전 단조성 + 서버가 보내는 최소 버전으로 막고, 서명 만료 필드는 v0.1에서 선택.

## 재검토 조건
- 노드가 1만 대를 넘거나 서명 키를 여러 사람이 다뤄야 할 때(TUF 수준의 키 위임·임계 서명).
- 자동 롤백이 한 달에 2번 이상 일어날 때(배포 전 시험 강화).
- 코드 서명 인증서를 도입할 때(Authenticode 서명 검증을 추가 겹으로).
