# S20 · PC방 환경 대응: 복원 솔루션·이미지 복제·LAN 캐시

| 항목 | 값 |
|---|---|
| 의존 | S10, S18, S19 |
| 권장 모델 | Opus 5.5 (effort 최대) |
| 규모 | XL |
| 사람 필요 | 끝에 실기 확인 — 실제 PC방(또는 비슷한 구성)에서 확인 |

이 차수는 `prompts/_PROTOCOL.md`를 따른다.

## 왜 중요한가
일반 PC용 소프트웨어는 PC방에서 이상하게 망가진다. PC방 PC는 보통 **하나의 마스터 이미지를 복제**해 깔고, **재부팅하면 C 드라이브가 원래대로 돌아가는 복원 솔루션**을 쓰며, 수십 대가 같은 인터넷 회선을 나눠 쓴다. 이걸 모르고 만들면: 모든 PC가 같은 신원을 갖거나, 재부팅마다 새 노드가 생기거나, 수십 대가 동시에 몇 GB 모델을 받아 매장 인터넷을 마비시킨다. 이 차수는 이 세 가지 현실을 정면으로 다룬다.

## 상세 요구사항

### 1. 영구 저장 위치
- 설정 `persistentDir`(설치 시 지정, 예: 복원되지 않는 D 드라이브). 신원 키, 캐시, 설정, 로그를 여기에 둔다.
- 시작할 때 영구성 점검: 표식 파일과 마지막 부팅 정보를 비교해 "이 폴더가 재부팅 후에도 남는가"를 추정하고 상태로 보고(확실하지 않으면 '알 수 없음').
- 영구 위치가 없으면(전부 복원됨): 신원은 매 부팅 새로 만들고 **이미지 코드로 재부착**(S10)해 같은 노드로 돌아간다. 모델 캐시는 매번 사라지므로 LAN 캐시가 사실상 필수 — 이 상황을 사장님 화면 경고로 보고.

### 2. 이미지 모드 신원
- 설치 프로그램(S21)이 마스터 이미지에 넣을 때는 '이미지 모드'로 설치: 신원 키를 만들지 않고, 매장 이미지 코드만 설정에 둔다.
- 첫 실행(또는 신원이 없을 때) 각 PC가 자기 키를 만들고 하드웨어 지문으로 등록·재부착.
- **복제 감지(클라이언트 쪽)**: 저장된 신원과 함께 저장한 지문 HMAC이 현재 하드웨어와 다르면, 그 신원은 복제된 것으로 보고 폐기한 뒤 재등록. 서버 쪽 복제 탐지(S10)와 함께 이중 방어.

### 3. LAN 캐시
- 매장의 PC 한 대(또는 카운터 PC)를 '캐시 노드'로 지정(설정 `cacheMode=server`). 캐시 노드는 서버가 서명한 매니페스트에 있는 아티팩트만 LAN에 HTTP로 제공한다(`/artifacts/<sha256>`, Range 지원).
- 접근 제한: 사설 IP 대역만, 매장 내 노드 인증 토큰(서버가 발급한 단기 토큰) 확인.
- 클라이언트는 LAN에서 받든 어디서 받든 **SHA-256·서명을 직접 검증**(캐시 노드를 믿지 않는다 — 오염돼도 피해 없음).
- 캐시 노드 주소는 서버가 매장 설정으로 내려준다(멀티캐스트 탐색 불필요, 단순하게). 캐시 노드가 없거나 응답 없으면 서버/CDN으로.
- 매장 단위 동시 다운로드 제한: 서버가 매장 안에서 동시에 외부에서 받는 노드 수를 제한(기본 1~2대)하고, 나머지는 캐시 노드가 다 받은 뒤 LAN으로 받게 조율.
- 캐시 노드도 손님이 앉으면 외부 다운로드를 멈춘다(LAN 제공은 대역폭 상한 하에 유지할지 설정).
- Windows 방화벽 규칙(LAN 프로필 한정)은 설치 프로그램(S21)이 캐시 모드 선택 시에만 추가.

### 4. 네트워크
- 프록시: `HTTPS_PROXY` 환경변수와 Windows 시스템 프록시 설정을 지원(WinHTTP 설정 읽기).
- 나가는 연결만 사용(443). 들어오는 포트는 캐시 노드의 LAN 포트뿐.
- 시계 차이: 서버 시각과 많이 다르면(기본 2분) 경고 보고 — 인증·리스 판단은 서버 시각 기준으로 하도록 이미 설계됐는지 확인.
- 매장 회선 보호: 다운로드 허용 시간대 + 손님 없음 + 매장 동시 제한 세 가지를 모두 지킨다.

### 5. 다중 GPU·특이 구성
- GPU가 2개 이상이면 v0.1에서는 가장 VRAM이 큰 하나만 사용(문서화). 통합 그래픽만 있는 PC는 등록은 되지만 작업 불가 상태로 보고.

### 6. 시뮬레이션 테스트
- 재부팅 복원 흉내: 영구 폴더를 지우고 재시작 → 이미지 코드로 같은 노드에 재부착(노드 수 그대로).
- 복제 흉내: 신원 폴더를 다른 '가상 하드웨어'로 복사해 실행 → 복사본이 신원 폐기·재등록, 원본은 정상.
- LAN 캐시: 캐시 노드 1 + 클라이언트 5, 외부 다운로드 1회만 일어나는지, 오염된 파일 거부, 캐시 노드 다운 시 우회.

### 7. `docs/PCBANG.md` (설치 담당자·사장님용, 쉬운 한국어)
- 복원 솔루션을 쓰는 매장의 설치 방법(영구 드라이브 지정, 마스터 이미지에 넣는 방법, 이미지 코드)
- 캐시 노드 정하는 법과 권장 PC 조건
- 인터넷 사용량 안내(언제, 얼마나 — 측정 전이면 '예상')
- 문제 해결

## 하지 말 것
- 특정 복원 솔루션 제품의 내부 동작에 의존하는 구현(일반적 판별만)
- LAN 캐시를 인터넷에 노출

## 수용 기준
1. `pnpm verify` 통과
2. 재부착·복제·LAN 캐시 시뮬레이션 테스트 통과
3. 매장 동시 다운로드 제한 테스트(서버·에이전트 통합)
4. 프록시 설정 테스트(환경변수, 가짜 시스템 설정)
5. `docs/PCBANG.md`, `docs/manual-tests/S20.md` 완성, HUMAN_TODO 추가, 상태 `DONE_NEEDS_HUMAN`

## 적대적 검토 포인트
- 이미지 코드 유출 시 피해 범위(그 매장에만 노드 추가 가능한지, 승인 절차, 속도 제한)
- LAN 캐시를 통한 공격(오염, 경로 조작, 매장 밖 접근)
- 재부팅마다 노드·신원이 쌓이는 경로

## 선택 확장
- 매장 회선 사용량 보고(시간대별 다운로드량)를 사장님 화면에
- 캐시 노드 자동 선정(가장 오래 켜져 있는 PC)
