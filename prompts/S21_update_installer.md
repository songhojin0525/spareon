# S21 · 자동 업데이트·설치 프로그램·Windows CI

| 항목 | 값 |
|---|---|
| 의존 | S19, S20 |
| 권장 모델 | Opus 5.5 |
| 규모 | XL |
| 사람 필요 | 끝에 실기 확인 — 실제 PC에 설치·업데이트·제거 |

이 차수는 `prompts/_PROTOCOL.md`를 따른다.

## 목표
수백 대 PC에 손으로 다시 설치하지 않고도 안전하게 고쳐 나갈 수 있어야 한다. 서명된 업데이트를 단계적으로 내보내고, 문제가 생기면 자동으로 되돌리며, 처음 설치는 명령 한 줄(무인 설치)로 끝나게 한다. 업데이트 채널은 그 자체로 가장 위험한 공격 경로이므로 서명 검증이 절대 우회되지 않아야 한다.

## 먼저 읽을 것
- ADR 0015, `docs/SIGNING.md`, `docs/PCBANG.md`(영구 드라이브·이미지 모드), `docs/AGENT.md`, `.github/workflows/ci.yml`

## 산출물
- 서버: 에이전트 릴리스 관리(초안 → 단계적 배포 % → 일시정지 → 완료 / 롤백), 매장 대상 지정, 버전 고정
- 릴리스 서명 도구(CLI)
- 에이전트: `internal/update/` + `cmd/binjari-updater/`
- 설치 프로그램: WiX Toolset 기반 MSI(다른 도구가 더 낫다면 ADR로 근거) — `apps/agent/installer/`
- CI: Windows 잡에서 빌드 → MSI 생성 → 설치·서비스 시작·중지·제거 연기 시험 → 산출물 업로드
- `docs/UPDATES.md`, `docs/INSTALL.md`(설치 담당자용 한국어), `docs/manual-tests/S21.md`

## 상세 요구사항

### 1. 릴리스 (서버)
- 릴리스 = 버전, 파일 목록(에이전트·헬퍼·업데이터), SHA-256, 서명된 매니페스트, 최소 호환 서버 버전.
- 배포: 비율(1% → 10% → 50% → 100% 등)과 대상 매장(파일럿 매장 먼저). 노드 선택은 노드 ID 해시 기준으로 결정적(같은 노드는 같은 그룹).
- 건강 지표 자동 감시: 새 버전 노드의 재연결 실패율·크래시 보고·작업 실패율이 기준을 넘으면 배포 자동 일시정지 + 운영자 알림.
- 매장별 버전 고정(문제 매장 격리용).

### 2. 업데이트 흐름 (에이전트)
1. `update.available` 수신 또는 주기 확인 → 서명·버전 확인(다운그레이드는 운영자가 명시한 롤백일 때만)
2. 손님 없음 + 작업 없음 + 다운로드 허용 시간일 때 내려받기(LAN 캐시 경로 사용) → 해시·서명 검증
3. `versions/<버전>/`에 풀기 → 업데이터 실행 → 서비스 중지 → `current` 포인터 교체 → 서비스 시작
4. 새 버전이 설정 시간(기본 2분) 안에 서버에 인증 성공하지 못하면 업데이터가 이전 버전으로 되돌리고 보고
5. 크래시 루프(10분 안 3회) → 자동 롤백 + 보고
- **설치 폴더가 복원되는 PC**(S20 판별): 업데이트해도 재부팅하면 되돌아간다. 이 경우 실행 파일을 영구 드라이브의 버전 폴더에서 실행하는 구조를 쓰거나, 불가하면 "마스터 이미지 업데이트 필요"를 사장님·운영자에게 보고(이 판단과 구조를 ADR로).

### 3. 설치 프로그램 (MSI)
- 속성: `ENROLL_CODE`, `SERVER_URL`, `PERSIST_DIR`, `IMAGE_MODE=1`(마스터 이미지용), `CACHE_MODE=server`, `REMOVE_DATA=1`(제거 시 캐시까지 삭제).
- 무인 설치 예: `msiexec /i binjari-agent.msi ENROLL_CODE=ABCD2345 PERSIST_DIR=D:\Binjari /qn` — INSTALL.md에 매장 유형별 예시.
- 설치 내용: 서비스 등록(자동 시작, 실패 시 재시작), 헬퍼 실행 구성(S18 방식), 캐시 모드일 때만 LAN 방화벽 규칙, 시작 메뉴 없이 조용히.
- 제거: 서비스·규칙·예약 작업 제거, 기본은 영구 데이터 보존(`REMOVE_DATA=1`이면 삭제).
- 코드 서명: CI 비밀값(인증서)이 있으면 서명, 없으면 서명 없이 빌드하고 경고. 인증서 준비는 HUMAN_TODO(백신 오탐·SmartScreen 경고 감소 이유 설명).

### 4. CI
- Windows 잡: Go 빌드(에이전트·헬퍼·업데이터) → 테스트 → WiX로 MSI → 관리자 권한으로 설치 → 서비스 상태 확인 → 중지 → 제거 → 잔여물 확인. 산출물(MSI, 바이너리, SHA-256) 업로드.
- 태그 푸시 시 릴리스 워크플로(S30에서 배포까지 연결)를 위한 준비.
- 원격 저장소가 없어 CI를 못 돌리면: 워크플로 문법 검증까지 하고 NEEDS-HUMAN(푸시해서 결과 확인)으로 기록.

## 하지 말 것
- 서명 검증을 끄는 옵션(개발 모드라도 별도 개발 키로 서명)
- UPX 같은 실행 파일 압축(백신 오탐 증가)
- 사용자 동의 없는 다른 소프트웨어 설치

## 수용 기준
1. `pnpm verify` 통과
2. 업데이트 테스트(가상 버전 폴더): 정상 업데이트, 해시 불일치 거부, 서명 불일치 거부, 인증 실패 → 자동 롤백, 크래시 루프 → 롤백
3. 단계적 배포 테스트: 비율·대상 매장·결정적 그룹·자동 일시정지
4. Windows CI 잡 성공(또는 원격 없음 → NEEDS-HUMAN 기록 + 로컬 문법 검증)
5. `docs/INSTALL.md`, `docs/UPDATES.md`, `docs/manual-tests/S21.md` 완성, 상태 `DONE_NEEDS_HUMAN`

## 적대적 검토 포인트
- 업데이트 채널 탈취 시나리오(서버 침해, 중간자) — 서명 키가 서버에 없다는 전제가 지켜지는지
- 롤백이 실패해 모든 PC가 멈추는 경로(업데이터 자체의 버그 대비)
- 업데이트 중 손님이 오는 경우

## 선택 확장
- 델타 업데이트(바뀐 파일만)
- 운영자 화면용 배포 진행 상황 API(S26에서 사용)
