"느려도 되는 대량 작업"(번역, 데이터 정리 등)은 이 사업에 가장 잘 맞는 수요다(BUSINESS_CONTEXT 4·8절). PC방 손님 없는 시간에 몰아서 처리하는 배치 API를 만든다. 수천 줄을 올려도 비용이 정확히 맞고, 서버가 재시작돼도 이어서 끝나야 한다.

## 상세 요구사항

### 1. 입력
- JSONL, 줄마다 `{ custom_id, method: "POST", url: "/v1/chat/completions", body }`. custom_id 중복 금지.
- 업로드 시 전체 검증: 줄별 오류 목록(줄 번호, 사유)을 돌려주고, 오류가 있으면 배치 생성 거부(또는 `allow_partial` 옵션 — 기본 꺼짐).
- 크기·줄 수 상한(설정). 파일은 암호화 저장, 보존 기한 적용.

### 2. 비용
- 배치 생성 시 모든 줄의 최대 비용 합계를 견적하고 한 번에 홀드(잔액 부족이면 거부). 배치 할인율은 설정값(기본 0 — 가격 정책은 S07 추천 참고).
- 줄마다 실제 비용 캡처, 실패 줄은 그 몫 해제, 끝나면 남은 홀드 전부 해제. **홀드 = 캡처 합 + 해제 합**이 정확히 맞아야 한다.

### 3. 처리
- 줄마다 작업(`batch_item`) 생성, 우선순위 낮음, 구매자 간 공정성 유지(S12 DRR).
- 마감: 기본 24시간 창(설정). 창 안에 못 끝낸 줄은 만료 + 해제.
- 서버 재시작 후 미완료 줄을 이어서 처리(상태는 DB에만 있다).
- 진행 상황: 전체·완료·실패 수, 예상 남은 시간(최근 처리 속도 기준, '추정' 표시).

### 4. 결과
- 결과 JSONL: 줄마다 `{ custom_id, response: { status_code, body } }` 또는 `{ custom_id, error }`. 입력 순서와 무관, custom_id로 매칭.
- 결과 파일 보존 기본 7일 후 삭제(설정).

### 5. 취소
- 취소 시 대기 중 줄은 즉시 취소·해제, 실행 중 줄은 완료되면 과금(정책 문서화) 또는 취소.

## 하지 말 것
- 외부 모델(Claude) 배치 라우팅(S16 범위 밖, v0.1에서는 배치는 오픈소스 모델만)
- 결과에 노드 식별 정보 포함

## 수용 기준
1. `pnpm verify` 통과
2. 1,000줄 배치가 가짜 에이전트로 끝까지 완료, 비용 대사(홀드 = 캡처 + 해제) 정확
3. 중간 취소 테스트, 잘못된 줄 검증 보고 테스트
4. 처리 도중 서버 재시작 → 이어서 완료(중복 과금 0)
5. 공정성 테스트: 대형 배치가 다른 구매자의 대화형 요청을 막지 않음

## 적대적 검토 포인트
- 거대 파일·악의적 JSONL(깊은 중첩, 긴 줄)로 메모리 고갈 — 스트리밍 파싱 사용 여부
- 줄 수 × 반올림 누적 오차
- 다른 구매자의 파일 ID 접근

## 선택 확장
- 배치 완료 웹훅(서명 포함)
- 결과를 CSV로 내려받기
