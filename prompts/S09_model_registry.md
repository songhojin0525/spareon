| 규모 | L |

## 목표
PC방에서 돌릴 모델과 런타임을 안전하게 관리한다: 무엇을 돌려도 되는지(상업 이용 라이선스), 파일이 진짜인지(SHA-256 + ed25519 서명), 과금용 토큰 수를 서버가 셀 수 있는지(토크나이저). 노드는 서명이 확인된 파일만 실행한다.

## 먼저 읽을 것
- ADR 0004·0009·0015, `docs/THREAT_MODEL.md`(공급망·아티팩트 행), `docs/BUSINESS_CONTEXT.md` 4·10절(PC방 GPU 메모리 한계)

## 산출물
- `apps/server/src/registry/` — 모델·아티팩트·런타임 릴리스 관리, 서명, 토크나이저 로더
- 저장소 추상화: `StorageDriver`(파일 시스템 — 개발용, S3 호환 — 운영용 인터페이스와 구현, 테스트는 파일 시스템과 가짜 S3)
- 에이전트용 아티팩트 내려받기 엔드포인트(인증, HTTP Range 지원)
- 구매자용 모델 목록(활성 모델만)
- CLI: `model:add`, `model:activate`, `model:retire`, `runtime:add`, `keys:generate-signing`
- `docs/MODEL_CANDIDATES.md`, `docs/SIGNING.md`
- S08의 `SKELETON(S09)`(입력 토큰 보수적 추정)를 실제 토크나이저 계산으로 교체

## 상세 요구사항

### 1. 서명
- 서명 키: ed25519. 개인키는 파일 경로(`ARTIFACT_SIGNING_KEY_FILE`)로만 받고 저장소에 두지 않는다. 공개키는 에이전트 빌드 설정에 내장(S17에서 사용). 키 생성 CLI 제공.
- 매니페스트: `{ kind, id, version, files: [{ name, sha256, size }], createdAt, minAgentVersion? }` — S02의 정규화 규칙으로 직렬화해 서명.
- 키 교체 계획(`docs/SIGNING.md`): 새 키를 미리 에이전트에 배포(두 키 모두 신뢰) → 전환 → 이전 키 폐기. 키 유출 시 대응 절차.

### 2. 모델 등록 규칙 (활성화 게이트)
- 필수: 라이선스 이름, 라이선스 URL, 출처 URL, `commercial_use_ok = true`, GGUF 아티팩트, 토크나이저 아티팩트, 최소 VRAM, 컨텍스트 길이, 양자화.
- 하나라도 빠지면 활성화 거부(명확한 에러). 활성화·은퇴는 감사 기록.
- `model:add --file <gguf> --tokenizer <tokenizer.json> ...`: SHA-256·크기 계산 → 저장소 업로드 → 매니페스트 서명.

### 3. 토크나이저 (과금의 근거)
- 서버가 모델별 토크나이저로 입력·출력 토큰 수를 센다(ADR 0009). Node에서 오프라인으로 `tokenizer.json`을 읽을 수 있는 라이브러리를 고르고 ADR로 남긴다(후보: Hugging Face 토크나이저 JS 구현).
- 작은 테스트용 토크나이저 fixture로 개수 테스트(대용량 모델 파일 없이).
- 토크나이저가 없는 모델은 활성화할 수 없다.

### 4. 아티팩트 내려받기
- `GET /agent/v1/artifacts/:sha256` — 노드 인증 필요(S10 이전에는 개발용 인증 + `SKELETON(S10)`), Range 요청 지원(이어받기), 정확한 Content-Length, 캐시 헤더.
- 운영 환경에서는 CDN 서명 URL로 리다이렉트하는 모드를 지원하되, 클라이언트는 어디서 받든 SHA-256과 서명을 직접 검증한다(전송 경로를 신뢰하지 않음).

### 5. 모델 후보 조사 (`docs/MODEL_CANDIDATES.md`)
- 기준: 상업 이용 가능 라이선스(Apache-2.0·MIT 우선, 조건부 라이선스는 조건 요약), 8GB VRAM에서 4K 컨텍스트 포함 Q4 양자화로 동작, 한국어 품질, 지시 따르기 튜닝, GGUF 공개 여부, 토크나이저 공개 여부.
- 웹 검색이 가능하면 후보 3~5개를 링크·라이선스·크기와 함께 표로. 불가하면 기준과 빈 표를 남기고 HUMAN_TODO에 "후보 확정" 추가.
- 라이선스 판단은 최종 확인이 아니라 1차 조사임을 명시한다.

## 하지 말 것
- 실제 대용량 모델 파일을 저장소에 커밋
- 라이선스 확인 없이 기본 활성 모델 지정

## 수용 기준
1. `pnpm verify` 통과
2. 서명 테스트: 정상 매니페스트 검증 성공, 한 바이트라도 바뀐 매니페스트·파일은 거부, 다른 키로 서명한 것은 거부
3. 활성화 게이트 테스트: 필수 항목 하나씩 빠뜨린 경우 모두 거부
4. 토크나이저 개수 테스트(fixture), Range 이어받기 테스트
5. `docs/SIGNING.md`, `docs/MODEL_CANDIDATES.md` 존재

## 적대적 검토 포인트
- 서명 검증 우회(매니페스트는 맞는데 파일이 다른 경우, 경로 조작 `../`)
- 개인키가 로그·에러·저장소에 남는 경로
- 라이선스 필드를 형식적으로만 채워 통과하는 구멍

## 선택 확장
- 모델 카드 자동 생성(크기, 필요 VRAM, 라이선스 요약)
- 아티팩트 사용 현황(어느 매장이 어떤 모델을 캐시했는지)
