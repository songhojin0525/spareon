# S04 · 걷는 뼈대 = 0단계 장난감

| 항목 | 값 |
|---|---|
| 의존 | S02, S03 |
| 권장 모델 | Opus 5.5 |
| 규모 | XL |
| 사람 필요 | 끝에 선택 — 친구 PC 2~3대로 직접 데모 |

이 차수는 `prompts/_PROTOCOL.md`를 따른다.

## 목표
로드맵 0단계를 실제로 돌린다: **남의 PC가 질문에 답하고, 그 결과가 장부에 남는다.** 구매자 요청 → 서버 → 에이전트(PC) → 응답 → 크레딧 이동까지 처음부터 끝까지 가늘게 연결한다. 이후 차수는 이 뼈대의 각 부분을 진짜로 교체해 나간다. 창업자가 "진짜 돌아간다"를 처음 보는 순간이므로, 데모가 확실히 돌아야 한다.

## 먼저 읽을 것
- `docs/ARCHITECTURE.md` 시나리오 ②, `docs/PROTOCOL.md`, `docs/DB.md`, `docs/BUSINESS_CONTEXT.md` 11절(로드맵 0단계)

## 원칙
- S02 프로토콜과 S03 스키마를 **그대로** 쓴다. 버릴 임시 형식을 만들지 않는다.
- 단순화한 부분은 모두 `// SKELETON(SNN): <대체 내용>`으로 표시하고 REPORT의 '교체 목록' 표에 적는다(무엇을, 어느 차수가 대체하는지).
- 단순화해도 **원장 불변식(통화별 합 0)과 손님 우선 원칙은 지킨다.**

## 산출물
- 서버: 최소 Fastify 앱
  - `POST /v1/chat/completions`(비스트리밍, OpenAI 형식 최소 부분), 환경변수의 개발용 API 키 1개로 인증 — `SKELETON(S05)`
  - 에이전트 WebSocket 엔드포인트, 개발용 공유 비밀(`DEV_AGENT_SECRET`)로 인증 — `SKELETON(S11)`
  - 단순 배정: 해당 모델을 가진 첫 번째 대기 노드 — `SKELETON(S12)`
  - 고정 단가 과금: 구매자 → 매장(70%) + 플랫폼(30%) 이동을 원장 테이블에 합 0 거래로 기록 — `SKELETON(S06, S08)`
  - `GET /dev` 개발용 대시보드(서버 렌더링 HTML, 2초 자동 새로고침): 노드 목록·상태, 최근 작업, 계정 잔액. `NODE_ENV=development` 또는 `DEV_DASHBOARD=1`일 때만 열린다.
- 에이전트(Go): `binjari-agent run` 콘솔 모드(Windows·macOS·Linux)
  - 서버 연결 → 인증 → capabilities 보고 → 작업 수락 → 런타임 실행 → 완료 보고
  - 런타임 어댑터: `fake`(결정적 출력, 토큰 수 보고) · `ollama`(로컬 `http://127.0.0.1:11434`의 채팅 API 호출, 비스트리밍)
  - 손님 감지: 이 차수에서는 `--always-available`만 지원 — `SKELETON(S18)`. Ctrl+C 시 진행 중 작업을 `job.preempted`로 보고하고 종료.
- Go가 없는 환경을 위해 TS 가짜 에이전트(`packages/testkit`의 `FakeAgent`)도 같은 프로토콜로 구현
- `pnpm demo`: 임시 Postgres + 서버 + 가짜 에이전트 2개(Go가 있으면 Go 에이전트 fake 런타임, 없으면 TS FakeAgent) → 요청 10개 → 전부 완료 → 잔액과 원장 합계를 표로 출력
- `docs/DEMO_0.md`: 친구 PC로 해 보는 법(아래)

## 상세 요구사항

### 1. 흐름의 정확성
- 요청 시 구매자 잔액 확인 → 작업 생성(입력은 S03 규칙대로 암호화 저장) → 노드에 `job.offer` → `job.accept` → `job.complete` → 과금 거래 1건(구매자 −, 매장 +, 플랫폼 +, 합 0) → 응답 반환.
- 노드가 2초 안에 수락하지 않으면 다음 노드. 15초 리스 안에 완료 소식이 없으면 실패 처리하고 다른 노드에 재시도(최대 2회). 최종 실패 시 과금하지 않는다.
- 같은 요청이 두 번 과금되지 않는다(완료 메시지 중복 수신 테스트).

### 2. DEMO_0.md (창업자가 그대로 따라 할 수 있게, 한국어, 초보자 기준)
- 준비물: 서버를 돌릴 내 PC, 친구 PC 2~3대(각자 Ollama 설치, 작은 모델 하나 pull — 모델 이름은 예시로만 쓰고 "가벼운 채팅 모델 아무거나"라고 적는다)
- 서버 실행 명령, 개발용 키 설정
- 친구 PC에서 에이전트를 실행하는 명령(Windows용 `.exe`를 만드는 `GOOS=windows go build` 명령 포함)
- 연결 방법 두 가지: ① 같은 와이파이(내 PC의 LAN IP) ② 다른 장소면 터널 서비스(예: Cloudflare Tunnel)로 임시 HTTPS 주소 만들기 — "개발용·임시로만, 쓰고 나면 끄기" 경고와 함께. 구체적 명령은 '확인 필요' 표시.
- 성공 확인법: `/dev` 대시보드에서 친구 PC가 '대기'로 보이고, 질문을 보내면 '작업 중' → 장부에 기록
- 문제 해결: 방화벽, 포트, Ollama 미실행, 모델 이름 불일치

### 3. 테스트
- E2E 테스트(가짜 런타임): 노드 2개, 요청 20개, 그중 노드 1개를 도중에 끊기 → 모든 요청이 완료되거나 명확히 실패, 이중 과금 없음, 원장 합 0, 실패 요청은 과금 없음.
- Ollama 어댑터는 가짜 HTTP 서버로 테스트한다(실제 Ollama 필요 없음).

2. `pnpm demo`가 사람 개입 없이 끝까지 돌고 "10/10 완료, 원장 합 0"을 출력

4. 모든 단순화가 `SKELETON(SNN)`으로 표시되고 REPORT 교체 목록과 일치(검사 스크립트 `scripts/check-skeleton.mjs`로 목록 출력)

## 적대적 검토 포인트
- 뼈대라도 돈이 생기거나 사라지는 경로가 없는가(재시도·중복 완료·타임아웃 경합)
- 데모용 설정이 실수로 운영 기본값이 될 위험
- Ctrl+C·연결 끊김 때 작업이 영원히 '실행 중'으로 남는 경로
