# S18 · 손님 감지·즉시 선점 (Windows)

| 항목 | 값 |
|---|---|
| 의존 | S17 |
| 권장 모델 | Opus 5.5 (effort 최대) |
| 규모 | XL |
| 사람 필요 | 끝에 실기 확인 — Windows PC에서 실제 마우스·키보드·게임으로 확인 |

이 차수는 `prompts/_PROTOCOL.md`를 따른다.

## 왜 중요한가
사장님께 드리는 약속은 하나다: **"손님이 앉으면 바로 멈춥니다. 게임에 영향이 없습니다."** 이 약속이 한 번이라도 깨지면 매장은 떠난다. 이 차수는 손님의 존재를 빠르고 확실하게 감지하고, 감지 즉시 연산을 멈추고 GPU를 비우는 경로를 만든다. 감지가 불확실하면 무조건 멈춘다.

## 먼저 읽을 것
- ADR 0011·0016, `docs/AGENT.md`, `docs/KNOWN_UNKNOWNS.md`, `docs/ARCHITECTURE.md`(시간 예산: 입력 → 프로세스 종료 0.5초, 입력 → VRAM 해제 p95 2초)

## 배경 (설계에 반드시 반영)
- Windows 서비스는 세션 0에서 돌아 사용자의 입력을 직접 볼 수 없다. 그래서 **사용자 세션에서 도는 작은 헬퍼**(`spareon-helper.exe`)가 입력·화면 상태를 서비스에 알린다.
- 입력 감지는 `GetLastInputInfo` 폴링(100ms)으로 한다. **저수준 키보드·마우스 훅(`SetWindowsHookEx` LL)은 쓰지 않는다** — 키로거처럼 보여 백신·게임 안티치트가 막거나 경고할 수 있고, 사생활 측면에서도 나쁘다(ADR 0011).
- PC방 PC는 보통 전용 계정으로 항상 로그인된 상태이고, 손님 '로그인'은 PC방 관리 프로그램 화면에서 일어난다. 관리 프로그램의 상태를 표준 방법으로 읽을 수는 없으므로, 입력·화면·GPU 사용으로 판단하고 관리 프로그램 연동은 꽂을 수 있는 자리만 만든다.

## 산출물
- `apps/agent/cmd/spareon-helper/` — 사용자 세션 헬퍼
- `apps/agent/internal/presence/windows/` — 헬퍼 실행·감시, 이름 있는 파이프(named pipe) IPC, GPU 사용 프로세스 감지, 전체 화면 감지
- `apps/agent/internal/policy/` — 적격 판정 엔진(순수 함수)
- `docs/PRESENCE.md`, `docs/manual-tests/S18.md`
- S04의 `SKELETON(S18)`(항상 작업 가능) 교체 — `--always-available`은 개발용 플래그로만 남기고, 운영 설정(서비스 모드)에서는 거부

## 상세 요구사항

### 1. 헬퍼 실행
- 서비스가 세션 변경 알림(`SERVICE_CONTROL_SESSIONCHANGE`)을 받아, 활성 대화형 세션마다 `WTSQueryUserToken` + `CreateProcessAsUser`로 헬퍼를 띄운다. 헬퍼가 죽으면 다시 띄운다(백오프). 대안(작업 스케줄러 '로그온 시 실행')은 ADR에 비교해 두고, 서비스 방식이 실패하는 환경을 위한 대체 경로로 구현한다.
- 헬퍼는 사용자 권한으로만 돈다. 관리자 권한 요구 금지.

### 2. 헬퍼가 보내는 것 (파이프, 100~250ms마다 + 변화 즉시)
- 마지막 입력 이후 경과 ms, 입력이 새로 생긴 순간의 이벤트(타임스탬프 포함 — 지연 측정 시작점), 앞 창 프로세스 이름, 전체 화면 여부, 세션 ID, 헬퍼 하트비트.
- 파이프 이름 `\\.\pipe\spareon-presence`, ACL: 인증된 사용자 쓰기·서비스 읽기만. 메시지 크기 상한, 형식 검증. 다른 프로세스가 가짜 '유휴' 신호를 보내 연산을 강제할 수 없도록, 헬퍼 프로세스 ID와 세션을 서비스가 확인(파이프 클라이언트 PID 조회).

### 3. 적격 판정 (순수 함수, 표로 문서화하고 전부 테스트)
작업 가능(Eligible) = 아래가 **모두** 참일 때만:
- 대화형 세션이 있으면 헬퍼가 정상(최근 하트비트)이고, 입력 유휴 ≥ `minIdleMinutes`
- 앞 창이 차단 목록(게임·관리 프로그램 손님 화면 등, 매장 정책 + 기본 목록)에 없고, 전체 화면 앱 없음
- 우리 런타임 외의 프로세스가 GPU 3D 엔진을 일정 이상 쓰지 않음(Windows 성능 카운터 `GPU Engine`의 프로세스별 사용률 — 제조사 무관)
- 매장 일정 안, GPU 온도 < 한도, 일시정지·킬스위치 아님, 서버 연결 정상
- 대화형 세션이 아예 없으면(로그인 화면) 유휴로 본다. **헬퍼가 있어야 하는데 없거나 응답이 없으면 Eligible이 아니다(fail-safe).**

### 4. 선점 경로 (가장 빠른 경로)
1. 헬퍼가 새 입력을 감지 → 즉시 파이프로 이벤트 전송(폴링 주기를 기다리지 않음)
2. 서비스가 받는 즉시 실행기 `Preempt(customerInput)` — 다른 처리보다 우선
3. 런타임 프로세스 종료: Windows Job Object에 묶어 둔 프로세스 트리를 `TerminateJobObject`로 즉시 종료(S19가 런타임을 Job Object에 넣는다 — 이 차수에서는 가짜 GPU 점유 자식 프로세스로 같은 경로를 구현·시험)
4. 종료 확인 → VRAM 해제 확인(nvidia-smi 또는 GPU 인터페이스로 우리 프로세스의 메모리 0 확인, 최대 2초 폴링)
5. 서버에 `job.preempted` 전송(전송은 종료를 기다리게 하지 않는다 — 병렬)
6. 지연 기록: 입력 시각 → 종료 시각 → VRAM 해제 시각, 지표로 보고
- 같은 이유로 **다운로드도 즉시 일시정지**한다(PC방 대역폭은 게임용, S19 캐시가 이 신호를 따른다).
- 선점 후 다시 Eligible이 되려면 `minIdleMinutes`를 처음부터 다시 채워야 한다.

### 5. 테스트
- 판정 엔진: 진리표 전체(조건 조합) 단위 테스트, 리눅스에서도 실행.
- 선점 경로: 가짜 '입력 이벤트' + 실제 자식 프로세스(메모리를 잡고 있는 더미)로 종료까지 시간 측정, Windows CI와 리눅스에서 실행(Job Object는 Windows, 프로세스 그룹은 리눅스).
- 파이프 프로토콜·ACL 테스트(Windows CI, 빌드 태그). CI에 대화형 데스크톱이 없어 실행 불가한 테스트는 조건을 명시하고 건너뛰되, 같은 내용을 수동 체크리스트로 옮긴다.

### 6. 수동 실기 체크리스트 (`docs/manual-tests/S18.md`, 초보자가 따라 할 수 있게)
- 준비: 에이전트 설치(개발 빌드), 테스트 서버 연결, 짧은 `minIdleMinutes`(1분) 설정
- 확인 1: 1분간 아무것도 안 함 → 상태 '작업 가능' → 테스트 작업 시작 확인
- 확인 2: 마우스 살짝 움직임 → `spareon-agent status`에서 선점 지연(입력 → 종료, 입력 → VRAM 해제) 확인, 기준 0.5초 / 2초
- 확인 3: 게임(또는 GPU를 쓰는 프로그램) 실행 중에는 아무리 기다려도 작업이 시작되지 않음
- 확인 4: 헬퍼 프로세스를 작업 관리자에서 종료 → 즉시 작업 불가 상태 → 헬퍼 자동 재시작
- 확인 5: 10회 반복해 지연 값 기록표 작성 → 결과를 Claude에게 알려 주기
- HUMAN_TODO에 항목 추가

## 하지 말 것
- 저수준 입력 훅, 화면 캡처, 키 입력 내용 수집(입력 '시각'만 쓴다)
- PC방 관리 프로그램 내부를 역공학하는 연동

## 수용 기준
1. `pnpm verify` 통과(Go 리눅스 테스트 + `GOOS=windows` 빌드)
2. 판정 엔진 진리표 테스트 전부 통과, fail-safe 경우(헬퍼 없음·하트비트 끊김·카운터 읽기 실패) 모두 '작업 불가'
3. 선점 경로 자동 테스트: 이벤트 → 더미 프로세스 종료 500ms 이내(리눅스·Windows CI)
4. Windows CI에서 파이프·Job Object 테스트 통과(실행 가능한 범위), 나머지는 수동 체크리스트로 이관
5. `docs/manual-tests/S18.md` 완성, HUMAN_TODO 추가, 상태는 `DONE_NEEDS_HUMAN`

## 적대적 검토 포인트
- 손님이 있는데 Eligible이 되는 모든 경로(카운터 오류, 헬퍼 위장, 시계 변경, 절전 복귀)
- 선점 경로가 막히는 경우(락 경합, 파이프 버퍼 가득, 로그 쓰기 지연)
- 백신·안티치트가 의심할 만한 동작

## 선택 확장
- 투명성 모드: 손님 없는 동안 바탕화면 구석에 "이 PC는 쉬는 시간에 AI 연산에 참여합니다" 작은 표시(손님이 오면 즉시 사라짐, 매장 설정)
- PC방 관리 프로그램 연동용 플러그인 인터페이스 문서와 예시(파일·레지스트리 신호 방식)
