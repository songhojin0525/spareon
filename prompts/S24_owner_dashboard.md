# S24 · 사장님 대시보드

| 항목 | 값 |
|---|---|
| 의존 | S06, S07, S10, S23 |
| 권장 모델 | Sonnet 5.5 |
| 규모 | L |
| 사람 필요 | 없음 |

이 차수는 `prompts/_PROTOCOL.md`를 따른다.

## 목표
PC방 사장님이 휴대폰으로 열어 "우리 PC들이 지금 뭘 하고 있고, 얼마를 벌었고, 전기요금은 얼마쯤 들었는지"를 10초 안에 이해하게 한다. 설치부터 멈춤 버튼까지 사장님이 혼자 할 수 있어야 한다. 이 화면이 파일럿(로드맵 1단계)의 얼굴이다.

## 먼저 읽을 것
- `docs/BUSINESS_CONTEXT.md` 7·13절, `docs/WEB.md`, `docs/ENROLLMENT.md`, `docs/LEDGER.md`(미성숙·확정 수익), `docs/ECONOMICS_REPORT.md`(정직한 범위 문장)
- 설치 안내 화면용: `docs/PCBANG.md`·`docs/INSTALL.md`가 있으면 그 내용을 쓴다. 아직 없으면(S20·S21 미완료) `prompts/S20_pcbang_environment.md`·`prompts/S21_update_installer.md`에 정의된 설치 속성(`ENROLL_CODE`, `PERSIST_DIR`, `IMAGE_MODE` 등)을 기준으로 만들고, REPORT의 '다음 차수에 미치는 영향'에 "S21 완료 후 설치 문구 재확인"을 남긴다.

## 산출물 (모두 `/owner` 아래)
- 홈: 오늘 요약(작업 중 PC 수, 손님 사용 중, 대기, 꺼짐), 오늘·이번 달 수익(확정 / 확정 대기 구분), 알림
- 매장 만들기 마법사: 매장 정보 → 전기요금 단가(모르면 기본값 + "고지서 보고 바꾸세요") → 운영 일정 → 설치 안내
- 매장 상세: PC 목록(상태 칩, 오늘 작업 시간, 온도, 마지막 연결), PC 이름 바꾸기, PC 끄기(비활성화), 승인 대기 PC 승인
- 설정: 주간 일정 편집기(30분 칸, 끌어서 선택, 모바일에서도 가능), 최소 대기 시간, 온도 한도, 다운로드 허용 시간, 손님 안내 표시 여부
- 설치: 등록 코드(일반·이미지용) 발급·폐기, QR, 설치 파일 받기 링크, 무인 설치 명령(복사 버튼), 복원 솔루션 매장용 안내(PCBANG.md 요약)
- 수익: 일별 막대 그래프(확정 / 대기 / 회수), PC별 순위, 전기요금 추정, 순수익 추정, "어떻게 계산했나요" 설명
- 정산 기록: 운영자가 기록한 수동 정산 목록(읽기 전용) + "파일럿 기간에는 운영자가 직접 정산합니다" 안내
- **매장 전체 멈춤** 버튼(크고 빨갛게, 확인 대화상자, 즉시 반영 확인 표시)

## 상세 요구사항

### 1. 상태 표시 (쉬운 말)
- 칩: "손님 사용 중", "AI 작업 중", "대기 중", "꺼짐", "멈춤", "점검 필요"(격리·런타임 불안정·업데이트 필요 등 — 눌러서 이유와 할 일 보기).
- 갱신: 5초 폴링(ETag로 변경 없으면 가볍게). 선택 확장으로 SSE.

### 2. 숫자의 정직함
- 수익은 원장에서만 가져온다(화면에서 계산 금지 — 서버 API가 원장 기반 집계를 제공). 확정 / 확정 대기(성숙 기간 중) / 회수됨을 구분하고, 확정 대기에는 "검증을 거쳐 N시간 뒤 확정" 설명.
- 원화 환산은 '약' 표시 + 사용한 환율·페그 표시.
- 전기요금: GPU 실측 전력(에이전트 보고)이 있으면 그것 × 시간 × 매장 단가, 없으면 가정값 — 어느 쪽인지 라벨로 표시. 기본요금 제외 이유 툴팁.
- 아직 실측이 없는 매장에는 S07의 "정직한 범위" 문장으로 예상 수익을 보여 주되 '예상'임을 크게 표시.

### 3. 알림
- PC가 운영 일정 중 30분 이상 꺼짐, 격리, 업데이트 필요(이미지 업데이트 포함), 영구 저장소 없음 경고, 디스크 부족. 앱 내 알림 목록(이메일·카카오 알림은 범위 밖).

### 4. 서버 API
- 필요한 집계 API(매장 요약, PC별 오늘 지표, 수익 일별 집계, 전기요금 추정)를 서버에 추가. 권한: 자기 매장만.

### 5. 시험
- 시드 데이터 + 가짜 에이전트/nodesim으로 상태 변화와 수익 발생을 만들어 E2E.
- **화면 숫자 = API·원장 값** 비교 테스트(수익, 확정 대기, 회수).
- 모바일 뷰포트 시나리오 전부, axe, 스크린샷 저장.
- 매장 전체 멈춤 → 가짜 에이전트가 `control.pause` 수신까지 E2E.

## 하지 말 것
- 출금 버튼·출금 요청 기능(법률 검토 전 없음)
- 화면에서의 돈 계산(전부 서버 집계)
- 구매자 정보·프롬프트 노출(사장님은 어떤 작업인지 내용을 볼 수 없다)

## 수용 기준
1. `pnpm verify` 통과
2. 마법사 → 코드 발급 → 가짜 에이전트 등록 → PC 목록에 표시 E2E
3. 상태 칩 전환 E2E(손님 사용 중 ↔ AI 작업 중 ↔ 대기)
4. 화면 숫자 = 원장 값 테스트, 측정/추정 라벨 테스트
5. 매장 멈춤 E2E, axe 심각 위반 0, 모바일 스크린샷 저장

## 적대적 검토 포인트
- 다른 매장 데이터 노출(ID 바꿔 요청)
- 숫자가 원장과 어긋나는 집계(시간대 경계, 성숙·회수 반영 시점)
- 사장님이 오해할 표현(확정 아닌 돈을 확정처럼, 예상을 약속처럼)
