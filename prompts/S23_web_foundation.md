## 목표
사장님·구매자·운영자 화면이 올라갈 웹의 기반을 만든다: Next.js 앱, 한국어 우선 다국어, 서버 세션을 쓰는 로그인, 역할별 영역, 접근성, 자동 화면 시험. 사장님은 대부분 휴대폰으로 볼 것이므로 처음부터 모바일 우선으로.

## 먼저 읽을 것
- ADR 0012(같은 출처 프록시), `docs/PERMISSIONS.md`, 서버 OpenAPI(`/api/openapi.json`), `docs/BUSINESS_CONTEXT.md` 13절(제품 원칙)

## 산출물
- `apps/web/` — Next.js(App Router, TypeScript strict), Tailwind CSS, next-intl(ko 기본, en)
- 기본 컴포넌트(접근성 고려): 버튼, 입력, 선택, 카드, 표, 대화상자, 알림(토스트), 배지, 상태 칩, 빈 상태, 로딩 스켈레톤, 확인 대화상자(위험 동작용)
- 레이아웃: `/owner`(사장님), `/app`(구매자), `/ops`(운영자) 각각의 셸과 내비게이션
- 인증 화면: 로그인, 회원가입(사장님/구매자 선택, 약관 동의), 로그아웃
- `docs/WEB.md` — 구조, 디자인 원칙, API 클라이언트 생성, 시험 방법

## 상세 요구사항

### 1. 서버 연동
- `next.config`의 rewrite로 `/api/*` → `SERVER_URL`(환경변수). 브라우저 입장에서 같은 출처라 세션 쿠키·CSRF가 단순해진다.
- 서버 OpenAPI에서 타입이 있는 클라이언트 생성(`openapi-typescript` + `openapi-fetch`), `pnpm --filter @spareon/web gen:api`. 생성물이 최신인지 검사.
- 서버 컴포넌트에서 세션 확인 → 역할에 맞지 않는 영역 접근 시 리디렉트. **권한의 진실은 서버**에 있고 웹은 숨기기만 한다(서버가 403이면 그대로 처리).
- CSRF 토큰은 서버(S05) 방식에 맞춰 상태 변경 요청에 자동 첨부.

### 2. 디자인 원칙
- 사장님 화면: 기술 용어 대신 쉬운 말("노드" 대신 "PC", "선점" 대신 "손님이 와서 멈춤"). 큰 글씨·큰 터치 영역, 390px 폭에서 깨지지 않음.
- 숫자는 정직하게: 측정값과 추정값을 시각적으로 구분(추정은 '약', '예상' 표시와 근거 툴팁).
- 위험한 동작(전체 멈춤, 키 폐기)은 확인 대화상자 + 무엇이 일어나는지 설명.
- 다크 모드 지원, 색만으로 의미 전달 금지(상태 칩에 글자 포함).
- 약관·개인정보 문구는 "초안 — 법률 검토 전" 배너와 함께 자리만 만든다.

### 3. 다국어
- 모든 UI 문자열은 메시지 파일 키로(하드코딩 금지 — 린트 또는 검사 스크립트로). 날짜·시간은 Asia/Seoul, 돈은 원·크레딧 형식 함수 하나로.

### 4. 시험
- Playwright: 환경변수 `PLAYWRIGHT_BROWSERS_PATH`가 있으면 그 브라우저를 쓰고, 없으면 `npx playwright install chromium` 안내(설치 시도 1회).
- E2E: 사장님 가입 → 로그인 → `/owner` 도착 / 구매자 가입 → `/app` / 운영자(CLI로 생성) → `/ops` / 다른 역할 영역 접근 차단 / 로그아웃.
- 접근성: `@axe-core/playwright`로 주요 화면 검사, 심각(serious 이상) 위반 0.
- 모바일 뷰포트(390×844) 스크린샷을 `docs/stages/S23/screens/`에 저장(사람 검토용).
- E2E는 테스트용 서버(임시 DB)를 띄워 실제 API로 돈다(목킹 금지).

## 하지 말 것
- 각 역할의 실제 기능 화면(S24~S26)
- 서버를 거치지 않는 인증, 브라우저 저장소에 토큰 보관

## 수용 기준
1. `pnpm verify` 통과, `pnpm --filter @spareon/web build` 성공
2. 인증·역할 E2E 전부 통과
3. axe 심각 위반 0
4. 하드코딩 문자열 검사 통과
5. 모바일 스크린샷 저장

## 적대적 검토 포인트
- 클라이언트에서만 막고 서버에서 안 막는 권한(서버 테스트로 이미 막혔는지 확인)
- 오픈 리디렉트(로그인 후 `next=` 파라미터), XSS(사용자 입력 표시)
- 쿠키 설정(Secure, SameSite)이 프록시 구성에서 깨지는지
