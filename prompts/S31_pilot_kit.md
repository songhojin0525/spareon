# S31 · PC방 파일럿 키트

| 항목 | 값 |
|---|---|
| 의존 | S30 |
| 권장 모델 | Opus 5.5 (주장-근거 대조 때문에) |
| 규모 | L |
| 사람 필요 | 끝에 필수 — 매장 섭외, 방문, 설치 |

이 차수는 `prompts/_PROTOCOL.md`를 따른다.

## 목표
로드맵 1단계 — 동네 PC방 1~3곳 파일럿 — 를 창업자가 혼자 진행할 수 있게 모든 자료와 도구를 준비한다. 가장 중요한 원칙: **사장님께 하는 모든 말이 실제 제품 동작과 측정값으로 뒷받침되어야 한다.** 측정 전인 것은 '목표'나 '예상'으로 쓴다. 파일럿의 통과 조건은 로드맵 그대로: "월 수익·전기요금 실측 완료".

## 먼저 읽을 것
- `docs/BUSINESS_CONTEXT.md` 7·11·13절, `docs/ECONOMICS_REPORT.md`, `docs/PCBANG.md`, `docs/INSTALL.md`, `docs/E2E_REPORT.md`, `docs/SECURITY_REVIEW.md`, `docs/manual-tests/*`의 실기 결과(있으면), HUMAN_TODO의 완료 항목

## 산출물 (`docs/pilot/`, 파일 이름은 영문, 내용은 한국어, 사장님이 읽는 문서는 쉬운 말)
- `intro.md`(소개서) — 한 장: 무엇인가, 사장님이 얻는 것, 손님 보호 약속, 보안, 전기요금, 정산 방식(파일럿 기간 수동), 그만두는 법
- `install-guide.md`(설치 안내) — 일반 매장 / 복원 솔루션 매장 / 마스터 이미지 매장별 단계, 캐시 PC 정하기, 확인 방법
- `faq.md` — 게임이 느려지나요? 전기요금은? 손님 개인정보는? 백신·안티치트 경고가 뜨면? 돈은 언제 들어오나요? 그만두려면? 문제가 생기면 누구에게?
- `agreement-draft.md`(파일럿 동의서 초안) — 기간, 범위, 정산, 데이터, 책임, 종료 — **"법률 검토 전 초안" 표시**
- `measurement-plan.md`(측정 계획) — 2주(설정 가능) 동안 무엇을 어떻게 측정하는지, 성공 기준, 매일 확인할 것
- `feedback-form.md`(피드백 양식), `operator-checklist.md`(운영자 체크리스트)(방문 전·설치일·1일차·1주차·종료)
- `tools/pilot-report/` — 파일럿 지표 내보내기: 매장·PC별 손님 없는 시간, 작업 시간, 수익(확정·대기), 선점 지연 p50/p95, GPU 온도, 측정 전력·kWh, 추정 전기요금, 순수익 → CSV + 마크다운 요약. 출력 형식은 `tools/econ-sim`의 가정 갱신 입력으로 쓸 수 있게(S07 연결).
- `docs/pilot/claims-evidence.md`(주장-근거표) — **자료 속 모든 주장 → 근거(코드 위치, 테스트, 측정 결과, 문서)** 표

## 상세 요구사항

### 1. 주장-근거 대조 (이 차수의 핵심)
- 소개서·FAQ·설치안내의 모든 사실 주장(예: "손님이 앉으면 바로 멈춥니다", "손님 PC의 파일에 접근하지 않습니다", "인터넷은 새벽에만 씁니다", "월 OO원 예상")을 뽑아 근거와 연결한다.
- 근거가 자동 테스트뿐이고 실기 측정이 없으면 표현을 '목표'로. 근거가 없으면 문장을 지우거나 고친다.
- `adversarial-reviewer`에게 "사장님 입장에서 속았다고 느낄 문장"을 찾게 한다.

### 2. 수익 표현
- S07의 정직한 범위 문장과 BUSINESS_CONTEXT 7절 가정을 그대로 쓰고, "파일럿에서 실제 숫자를 함께 확인합니다"를 강조. 약속처럼 보이는 표현 금지.

### 3. 측정 계획
- 측정 항목과 출처(에이전트 지표, 원장, 전력), 매일 확인 방법(사장님 화면 / 운영자 화면), 성공 기준(데이터 완결성, 손님 불만 0건, 선점 지연 목표 충족, 실측 수익·전기요금 확보), 중단 기준(손님 불만, 성능 문제 등 — 즉시 멈춤 절차).
- 파일럿 종료 후: `tools/pilot-report` → `tools/econ-sim` 가정 갱신 → 보고서 재생성 순서.

### 4. 섭외 준비
- 첫 방문 대화 흐름(5분 버전), 예상 질문 답, 데모 방법(사장님 휴대폰으로 화면 보여 주기 — 테스트 매장 데이터).

## 하지 말 것
- 측정 안 된 수치를 확정적으로 표현
- 법률 문서를 완성본처럼 표현
- 경쟁사 비방

## 수용 기준
1. `pnpm verify` 통과
2. `docs/pilot/` 문서 전부 존재, 주장-근거표의 모든 행에 근거 또는 '목표/예상' 표시
3. `tools/pilot-report`가 시드 데이터로 CSV·요약을 만들고, econ-sim 갱신 경로 테스트 통과
4. 적대적 검토의 '속았다고 느낄 문장' 지적 반영
5. HUMAN_TODO에 섭외·방문·동의서 법률 검토 항목, 상태 `DONE_NEEDS_HUMAN`

## 적대적 검토 포인트
- 과장, 빠진 위험 고지(백신 경고, 인터넷 사용, 정산 지연)
- 사장님이 그만두고 싶을 때 어려운 구조
- 손님(제3자)에 대한 고지 누락

## 선택 확장
- 소개서를 인쇄용 한 장 PDF로 만드는 스크립트
- 파일럿 진행 상황을 한 화면에 보여 주는 운영자 콘솔 페이지
